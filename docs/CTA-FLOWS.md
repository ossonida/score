# Score Counter CTA 흐름 명세

이 문서는 버튼의 위치나 화면 모양이 아니라 **사용자 상태에 따른 CTA의 노출, 실행 액션, 완료 결과**를 정의한다. CTA 동작을 변경할 때는 구현보다 먼저 이 문서를 수정하고 합의한다.

## 1. 공통 규칙

1. 같은 사용자 의도를 가진 CTA는 같은 액션 함수를 호출한다.
2. CTA의 노출, 문구, 활성 상태는 하나의 상태 계산 결과로 결정한다.
3. 화면마다 같은 로직을 복제하거나 숨겨진 버튼의 `.click()`을 호출하지 않는다.
4. 액션 함수는 `진입 조건 확인 → 상태 생성 → 화면 전환 → 검증 → 완료/복구` 순서를 따른다.
5. 모달을 닫는 `취소`와 데이터를 폐기하는 `기록 취소`를 구분한다.
6. 새로고침 후 복원이 필요한 흐름은 임시 상태를 저장하고, 완료 또는 명시적 취소 시에만 제거한다.
7. CTA 수정 시 정상 완료뿐 아니라 뒤로 가기, 닫기, 새로고침, 중복 클릭을 함께 검증한다.
8. 하단 메뉴(홈·통계·게임·설정)는 다른 화면이면 그 화면으로 이동하고, 이미 보고 있는 화면의 버튼을 누르면 그 화면 맨 위로 스크롤한다.

## 2. CTA 상태 모델

CTA 판단에 필요한 최소 상태는 다음과 같다.

| 상태 | 의미 |
| --- | --- |
| `boardPlayers` | 현재 메인 점수판의 플레이어 목록 |
| `boardMode` | `score`, `win`, `rank`, `coop` 중 현재 기록 방식 |
| `activeSession` | 진행 중인 점수 게임 정보 |
| `scorelessDraft` | 작성 중인 점수 없는 기록 |
| `authState` | `guest`, `signed-in`, `checking` |
| `networkState` | `online`, `offline` |

버튼은 DOM 존재 여부로 상태를 추론하지 않고 위 상태에서 파생된 CTA 모델을 사용한다.

```text
resolveCtaState(appState)
  → visible
  → enabled
  → label
  → ariaLabel
  → action
```

## 3. 메인 점수판 CTA

### 3.1 플레이어 추가

| 현재 상태 | CTA 위치 | 노출 문구/이름 | 실행 액션 | 완료 결과 |
| --- | --- | --- | --- | --- |
| 플레이어 0명 | 빈 화면 중앙 | 플레이어 추가하기 | 여러 명 추가 열기 | 1명 이상 추가 후 점수판 시작 |
| 플레이어 0명 | 우측 상단 | 랜덤 플레이어 한 명 추가 | 이름·색상 입력 없이 랜덤 플레이어 즉시 추가 | 1명 플레이어로 점수판 시작 |
| 플레이어 1명 이상 | 우측 상단 | 랜덤 플레이어 한 명 추가 | 이름·색상 입력 없이 랜덤 플레이어 즉시 추가 | 기존 점수와 플레이어를 유지하고 1명 추가 |
| 개인전·순위·협력 결과 입력 중 | 우측 상단 | 랜덤 플레이어 한 명 추가 | 이름·색상 입력 없이 현재 결과에 랜덤 플레이어 즉시 추가 | 현재 결과 목록에 1명 추가 |
| 팀전 결과 입력 중 | 우측 상단 | 플레이어 한 명 추가 | 한 명 추가 창에서 이름·색상·소속 팀 지정 | 선택한 팀에 1명 추가 |

고정 조건:

- 플레이어 0명일 때 중앙 CTA는 `여러 명 추가`, 우측 상단 CTA는 랜덤 플레이어 한 명 즉시 추가를 실행한다.
- 플레이어가 생기면 우측 상단 CTA는 팀 선택이 필요한 팀전 결과에서만 입력창을 열고, 나머지 화면에서는 랜덤 플레이어를 즉시 추가한다.
- 여러 명 추가 화면에서 선택한 기존 플레이어와 자동 생성 인원의 합이 실제 추가 인원이다.
- 팀전 한 명 추가를 취소하면 기존 결과 상태를 변경하지 않는다.

### 3.2 개별 플레이어 삭제

| 진입 방식 | 실행 액션 | 확인 | 완료 결과 |
| --- | --- | --- | --- |
| 플레이어 카드를 왼쪽으로 밀기 | 해당 플레이어 즉시 삭제 | 묻지 않음 | 점수 기록은 이름·점수 삭제, 결과 기록은 이름·결과 삭제 |
| 플레이어 이름 → 수정창 → 삭제 | 해당 플레이어 삭제 | 확인창 표시 | 확인 시에만 삭제 |

- 어떤 기록 방식에서도 마지막 플레이어까지 삭제할 수 있다. 마지막 플레이어가 삭제되면 작성 중인 결과 초안을 종료하고 플레이어 0명의 메인 화면으로 이동한다.
- 순위 기록에서 삭제하면 남은 플레이어의 순위를 즉시 다시 계산한다.
- 결과 기록에서 삭제한 플레이어는 기록 방식을 다시 변경해도 복원하지 않는다. 점수 기록으로 돌아갈 때도 남은 플레이어의 기존 점수만 복원한다.
- 왼쪽으로 미는 동안 카드 아래의 빨간 삭제 영역은 이동 거리에 맞춰 끝까지 부드럽게 드러난다.
- 두 진입 방식은 같은 삭제 상태 갱신 함수를 사용하고 확인 여부만 다르게 처리한다.

### 3.3 점수 초기화

| 진입 조건 | 확인 문구 | 완료 | 취소 |
| --- | --- | --- | --- |
| 플레이어 1명 이상, 점수 기록 모드 | 모든 플레이어의 점수를 0으로 초기화 | 이름·색상·순서는 유지하고 점수만 0 | 변경 없음 |

점수 없는 결과 입력 중에는 노출하지 않는다.

### 3.4 플레이어 전체 리셋

| 진입 조건 | 확인 문구 | 완료 | 취소 |
| --- | --- | --- | --- |
| 플레이어 1명 이상, 점수 기록 모드 | 추가된 플레이어와 점수를 모두 삭제 | 점수판을 빈 상태로 전환 | 변경 없음 |
| 점수 없는 결과 입력 중 | 플레이어 전체 리셋 | 점수 없는 임시 기록과 원래 점수판의 플레이어를 모두 삭제하고 빈 점수판으로 전환 | 결과 입력 유지 |

서로 다른 두 액션을 같은 핸들러에서 분기하더라도 사용자 문구와 확인 내용은 현재 모드에 맞아야 한다.

### 3.5 게임 종료 / SAVE

기록 방식이 점수·승패·순위·협력 중 하나로 변경되어도 우측 상단 툴바의 순서와 사용자 의도는 유지한다. 단, 점수 초기화는 점수 기록 모드에서만 노출한다. `SAVE`는 현재 방식의 기록 저장을 진행하고, 플레이어 추가는 현재 결과에 한 명을 추가한다. 버튼 문구와 접근성 이름도 기록 방식 전환만으로 바꾸지 않는다.

| 현재 상태 | CTA | 활성 조건 | 실행 액션 | 완료 결과 |
| --- | --- | --- | --- | --- |
| 점수 게임 진행 중 | SAVE | 플레이어 1명 이상 | 게임·날짜·장소 입력 열기 | 현재 점수판을 유지한 채 기록 저장 진행 |
| 점수 없는 승패 입력 중 | SAVE | 모든 플레이어 결과 입력 | 게임·날짜·장소 입력 열기 | 결과와 임시 상태 유지 |
| 점수 없는 순위 입력 중 | SAVE | 1위부터 모든 순위 유효 | 게임·날짜·장소 입력 열기 | 결과와 임시 상태 유지 |

구현 조건:

- 상단 `SAVE`는 기록 방식과 관계없이 같은 문구·위치·색상을 유지하며 현재 모드에 맞는 저장 액션을 직접 호출한다.
- 숨겨진 하단 저장 버튼을 대신 클릭하지 않는다.
- 저장 중에는 중복 클릭을 막고 성공 또는 실패 상태를 명확히 표시한다.
- 저장 완료는 입력 화면을 종료하는 액션이 아니다. 점수·개인전 승패·팀전 승패·순위 기록 모두 현재 방식과 플레이어, 점수·결과를 유지한다.

| 저장 상태 | 노출 CTA | 실행 액션 및 완료 결과 |
| --- | --- | --- |
| 점수 입력 후 게임 정보 저장 성공 | 기존 SAVE·플레이어 편집·리셋 | 기록 사본 저장, 현재 점수판과 점수 유지 |
| 개인전·팀전 승패 또는 순위 입력 후 게임 정보 저장 성공 | 기존 SAVE·기록 방식 변경·리셋 | 기록 사본 저장, 현재 결과 화면과 입력·게임 정보 유지 |
| 저장 완료 후 새로고침 | 같은 기록 방식의 CTA | 동일한 플레이어·팀 구성·승패·순위 복원 |
| 저장 실패 또는 저장창 닫기 | 현재 입력 화면의 CTA | 현재 내용과 기존 저장 기록 유지 |
| 명시적인 플레이어 삭제·리셋·기록 취소 | 기존 삭제·취소 액션 | 해당 입력만 정리, 이미 저장한 기록은 유지 |

### 3.5 기록 방식 변경

플레이어가 1명 이상일 때 메인 화면 하단에 `기록 방식 변경` CTA를 노출한다. 플레이어가 없을 때는 기록 방식 CTA를 노출하지 않는다.

| 현재 기록 방식 | 선택창에 노출할 CTA |
| --- | --- |
| 점수 기록 | 승패 기록 · 순위 기록 · 협력 기록 |
| 승패 기록 | 승패 기록(개인전·팀전 전환) · 점수 기록 · 순위 기록 · 협력 기록 |
| 순위 기록 | 점수 기록 · 승패 기록 · 협력 기록 |
| 협력 기록(4가지 방식 중 하나) | 점수 기록 · 승패 기록 · 순위 기록 · 협력 기록(다른 협력 방식으로 전환) |

`협력 기록`을 누르면 `협력 기록 방식` 단계로 이동한다.

| 협력 방식 | 입력 | 저장 활성 조건 | 저장 값 |
| --- | --- | --- | --- |
| 성공·실패·점수형 | 경기 전체 성공·실패, 공동 점수(선택) | 결과 선택, 점수 유효 | `cooperativeResult`, `sharedScore`(선택) |
| 미션형 | 아래 '협력 미션 기록' 표 | 시도 1회 이상 | `missionAttempts` |
| 난이도형 | 난이도 선택(게임별 목록, 없으면 입문·보통·어려움·최고 / 판데믹 입문·보통·영웅·전설) + 성공·실패 | 난이도와 결과 선택 | `cooperativeResult`, `difficulty` |
| 캠페인형 | 시나리오 번호(‹ ›, 1~999) + 시나리오 레벨(선택, 0~7, 누른 레벨을 다시 누르면 해제) + 성공·실패, 같은 게임·시나리오 시도 횟수는 기록에서 자동 계산 | 결과 선택 | `cooperativeResult`, `scenario`, `scenarioLevel`(선택) |

- 선택 단계에는 현재 사용 중인 협력 방식을 빼고 노출하며, `기록 방식으로`는 이전 단계로 돌아가고 입력은 유지한다.
- 최근 협력 기록이 있으면 게임별 최신 1개를 `게임 · 방식 · 마지막 값` 칩(최대 3개)으로 보여 주고, 누르면 그 게임·방식·난이도(캠페인은 갈래로 열리는 게임이 많아 마지막 시나리오 번호와 레벨을 그대로, 미션은 다음 미션)를 미리 선택한 채 시작한다.
- 기존 기록은 변환하지 않는다. 미션 시도가 있으면 미션형, `scenario`가 있으면 캠페인형, `difficulty`가 있으면 난이도형, 나머지 협력 기록은 성공·실패·점수형으로 읽는다.

고정 조건:

- 현재 사용 중인 기록 방식은 선택창에 중복 노출하지 않는다.
- `기록 방식 변경`은 모든 기록 방식에서 같은 선택창과 같은 전환 함수를 사용한다.
- 선택창을 닫으면 현재 기록 방식과 입력 내용을 그대로 유지한다.
- 점수 기록에서 다른 방식으로 이동할 때 현재 점수판을 스냅샷으로 보존한다.
- 승패·순위·협력 기록에서 점수 기록으로 돌아오면 삭제되지 않은 플레이어의 전환 전 점수를 복원한다.
- 승패·순위 사이를 전환할 때 참가자·이름·색상·추가 플레이어는 유지하고 방식별 결과만 초기화한다.
- 결과 입력 중 삭제한 참가자는 이후 어떤 기록 방식으로 전환해도 다시 추가하지 않는다.
- 결과 입력 중 플레이어를 추가하거나 이름·색상을 수정하면 점수 기록의 기준 명단에도 즉시 반영한다. 새 플레이어가 점수 기록으로 돌아갈 때의 초기 점수는 0점이다.
- 협력 기록은 경기 전체의 성공·실패와 선택적인 공동 점수를 입력한다. 상세 저장·집계 기준은 7절을 따른다.
- 협력 미션 기록은 협력 기록과 같은 `coop` 결과 화면을 쓰되 `경기 전체 결과` 대신 `미션 진행` 영역을 보여준다. 공동 점수는 받지 않는다.

#### 협력 미션 기록 (플레이하며 기록)

| CTA | 조건 | 실행 | 보존 조건 |
| --- | --- | --- | --- |
| 이전 미션 `‹` / 다음 미션 `›` | 미션 1~999 범위 | 현재 도전 미션 번호만 변경 | 이미 기록한 시도는 유지 |
| 이어하기 칩 `게임 · 미션 N부터` | 시도 0회이고 이전 미션 기록이 있을 때 | 현재 미션을 N으로, 저장할 게임을 그 게임으로 설정 | 첫 시도 후 칩 숨김 |
| 실패 | 항상 | 현재 미션 실패 1회 추가, 같은 미션 유지 | 임시 기록에 즉시 보존 |
| 성공 | 항상 | 현재 미션 성공 1회 추가 후 다음 미션으로 이동 | 임시 기록에 즉시 보존 |
| 되돌리기 | 시도 1회 이상 | 마지막 시도 1개 삭제, 그 시도의 미션으로 복귀 | 이전 시도 유지 |
| 하단 `끝내고 저장 · 시도 N · 클리어 M` | 시도 1회 이상 | 기존 저장 대화상자(게임·날짜·장소) 열기 | 시도 0회면 비활성 `미션 결과 선택` |

- 한 세션(저장 1회)은 기록 1개, 플레이 1판이다. 시도 내역은 `missionAttempts`로 저장한다.
- 세션 결과(`cooperativeResult`)는 미션을 하나라도 성공했으면 성공, 아니면 실패로 자동 결정하며 기록 수정에서 바꾸지 않는다.
- 새로고침·앱 재시작 후에도 시도 내역과 현재 미션을 복원한다.
- 새로고침 후에는 확정된 현재 기록 방식과 해당 임시 상태를 복원한다.

## 4. 점수 없는 게임 기록 CTA

### 4.1 진입 경로

| 진입 상태 | 노출 CTA | 참가자 처리 | 다음 단계 |
| --- | --- | --- | --- |
| 메인 플레이어 0명 | 기록 방식 CTA 없음 | 먼저 플레이어 추가 | 점수 기록 시작 |
| 메인 플레이어 1명 이상 | 기록 방식 변경 | 현재 점수판 플레이어를 그대로 사용 | 기록 방식 선택 → 결과 입력 |

빈 메인 화면의 `점수가 없는 게임 기록하기` CTA는 제거한다. 플레이어를 먼저 추가한 뒤 기록 방식을 변경한다.

### 4.2 플레이어 0명일 때

```text
플레이어 추가하기
→ 점수 기록 화면
→ 기록 방식 변경
→ 승패 기록 · 순위 기록 · 협력 기록 중 선택
```

### 4.3 플레이어 1명 이상일 때

```text
기록 방식 변경
→ 현재 점수판 플레이어 스냅샷 생성
→ 현재 방식을 제외한 3개 방식 중 선택
→ 현재 플레이어 결과 입력
→ SAVE
→ 게임·날짜·장소 선택
→ 기록 저장
→ 기록 저장 후 현재 기록 방식과 입력한 결과 유지
```

고정 조건:

- 점수 없는 기록을 시작해도 기존 점수판의 이름, 색상, 점수와 진행 세션을 덮어쓰지 않는다.
- 결과 입력 화면에서 추가한 플레이어는 점수 없는 기록에만 반영한다.
- 이름 수정도 임시 결과 목록에만 반영하고 기존 점수판 이름을 임의로 바꾸지 않는다.
- 새로고침하면 작성 중인 단계와 결과를 복원한다.
- 저장 성공 후에도 현재 결과와 선택한 게임 정보를 초안에 유지한다. 명시적인 `기록 취소`, 플레이어 리셋·전체 삭제, 점수 기록으로의 전환에서 기존 정리 동작을 실행한다.
- 저장된 기록은 입력 화면의 사본이다. 저장 후 입력을 수정하거나 삭제해도 이미 저장한 기록은 바뀌지 않는다.

| 개인전 | 플레이어별 승리·무승부·패배 선택 | 모든 플레이어가 하나의 결과를 가짐 |
| 팀전 | 2~4팀 구성 후 팀별 승리·무승부·패배 선택 | 모든 팀이 하나의 결과를 가지며 모든 플레이어가 팀에 배정됨 |
| 순위 기록 | 추가 순서대로 1위부터 표시, 손잡이 드래그로 재정렬 | 모든 플레이어가 중복 없는 연속 순위를 가짐 |
| 점수 기록 | 기존 점수판으로 복귀 | 전환 전 이름·색상·점수·순서 복원 |
| 협력 기록 | 협력 방식 선택 후 방식별 입력(3.5 협력 방식 표), 참가자 | 방식별 저장 활성 조건 충족 시 저장 활성 |
| 기록 방식 변경 | 현재 방식을 제외한 3개 CTA 표시 | 선택 전까지 현재 입력 내용 유지 |

| 액션 | 의미 | 데이터 처리 |
| --- | --- | --- |
| 게임 정보 모달 닫기 | 결과 화면으로 돌아가기 | 입력한 결과와 초안을 유지 |
| 인원 선택 모달 닫기 | 작성 중단 | 확인 후 초안 폐기 또는 계속 작성 |
| 결과 화면의 기록 취소 | 전체 점수 없는 기록 취소 | 초안 제거 후 원래 점수판 복원 |

| 기록 방식 선택창 닫기 | 변경 취소 | 현재 방식과 입력 내용 유지 |

### 4.6 승패 기록의 개인전·팀전

- `승패 기록`을 선택하면 `개인전`과 `팀전`을 먼저 선택한다.
- 개인전은 기존 플레이어별 승패 입력 UI를 사용한다.
- 팀전은 플레이어가 2명 이상일 때 선택할 수 있고 2~4팀을 지원한다. 팀 수는 플레이어 수를 넘을 수 없다.
- 팀전 최초 진입 시 플레이어 추가 순서대로 각 팀에 번갈아 자동 배정한다.
- 팀 구성 화면에서 팀 이름을 수정하고 플레이어를 눌러 다음 팀으로 이동할 수 있다.
- 개인전과 팀전 결과 CTA는 짧게 `승`, `무`, `패`로 표시한다.
- 개인전은 한 플레이어의 결과를 선택하면 전체 결과를 다시 계산한다. 선택자가 승이면 나머지는 패, 선택자가 패면 나머지는 승, 무승부면 모두 무승부로 입력한다.
- 팀전 결과 화면에서는 팀 단위로 승리·무승부·패배를 선택한다. 한 팀 승리 선택 시 나머지 팀은 패배, 무승부 선택 시 모든 팀은 무승부가 된다.
- 팀전 결과 카드의 첫 줄에는 팀명과 `승`·`무`·`패` CTA를 양쪽에 배치한다. 팀별 카드는 포함된 첫 플레이어의 랜덤 색상을 사용한다. 참가자는 `닉네임 ×` 칩으로 표시하며 닉네임은 수정, `×`는 확인창 없이 해당 참가자를 삭제한다.
- 팀전 참가자 칩을 길게 누르면 확대·떠오름·대비 테두리로 드래그 선택 상태를 표시한다. 진동을 지원하는 기기에서는 선택 순간 짧게 한 번 진동한다. 첫 터치의 사용자 활성화가 아직 없거나 호출이 거절된 경우, 드래그 종료 터치에서 한 번만 재시도한다. 진동 미지원·차단 시에도 시각 효과와 이동은 유지한다. 다른 팀 카드 위에서 놓으면 해당 팀으로 이동한다. 빈 팀이 생기지 않도록 팀의 마지막 참가자는 이동하지 않는다.
- 팀전 결과 카드를 왼쪽으로 스와이프하면 해당 팀과 참가자를 확인창 없이 삭제한다. 팀전은 최소 2팀을 유지하므로 2팀만 남은 상태에서는 팀 삭제를 실행하지 않는다.
- 참가자 칩에서 시작한 제스처는 팀 카드 스와이프 삭제를 실행하지 않는다. 드래그가 취소되거나 팀 밖에 놓이면 소속을 유지한다. 팀 이동 후에는 소속이 바뀐 두 팀의 결과를, 팀 삭제 후에는 남은 모든 팀의 결과를 다시 선택한다. 삭제한 참가자는 다른 기록 방식으로 전환해도 복원되지 않는다.

| 팀전 결과 상태 | 제스처/CTA | 실행 액션 |
| --- | --- | --- |
| 참가자가 2명 이상인 팀 | 참가자 칩 길게 누른 뒤 다른 팀에 놓기 | 소속 이동, 결과 초기화, 진행 중 기록 저장 |
| 참가자가 1명인 팀 | 마지막 참가자를 다른 팀에 놓기 | 이동하지 않고 최소 인원 안내 |
| 3~4팀 | 카드 빈 영역·제목 영역에서 왼쪽 스와이프 | 팀과 소속 참가자 삭제, 결과 초기화, 진행 중 기록 저장 |
| 2팀 | 팀 카드 왼쪽 스와이프 | 삭제하지 않고 최소 2팀 안내 |
| 모든 팀 | 닉네임 짧게 누르기 / × | 기존 이름 수정 / 참가자 삭제 |
- 팀전 결과 화면에서 플레이어 추가 시 소속 팀을 선택하며, 플레이어 수정창에서도 팀을 변경할 수 있다.
- 팀 정보는 플레이어의 `teamId`, `teamName`으로 기록에 보존하여 개인 통계와 팀 기록을 구분할 수 있게 한다.

## 5. 게임 기록 저장 CTA

### 5.1 점수 게임 저장

```text
SAVE
→ 게임 종료 다이얼로그
→ 점수 저장
→ 1단계: 게임 검색·최근 게임·BGG 게임 ID에서 게임 선택
→ (BGG 확장이 있는 본판이면) 1단계 안에서 함께 사용한 확장 선택 → 다음
→ 2단계: 선택한 게임·날짜·장소·승리 조건 확인
→ 기록 저장
→ 성공 안내
```

게임 검색 결과나 최근 게임을 선택하면 즉시 2단계로 이동한다. 단, BGG 게임 정보에 확장이 있는 본판을 고르면 1단계에 확장 선택을 열고 `다음`으로 2단계에 간다. 검색 결과에서 확장을 고르면 그 확장의 본판을 선택하고 고른 확장을 미리 선택한다. 확장 정보는 BGG 게임 정보로 확인하며, 받을 수 없으면(비로그인·오류) 지금처럼 바로 2단계로 간다. 직접 입력한 게임명과 BGG 게임 ID는 `다음`으로 2단계에 확정한다. 2단계의 `게임 다시 선택`은 입력한 날짜·장소·승리 조건을 유지한 채 1단계로 돌아간다.

`초기 화면으로 돌아가기`는 현재 점수판만 비우며 이미 저장된 기록을 삭제하지 않는다.

### 5.2 저장 공통 검증

두 저장 모달의 표시 및 CTA는 다음 상태표를 따른다. 초기 `게임 기록하기` 설정 흐름에는 적용하지 않는다.

| 상태 | 입력 및 표시 항목 | 노출 CTA | 실행 액션 |
| --- | --- | --- | --- |
| 모든 기록 방식 → `경기 기록 저장` 1단계(제목 `게임 검색`) | 게임 검색·최근 게임·BGG 게임 ID | 다음 · 취소 | 검색 결과나 최근 게임 선택 시 즉시 2단계 이동, 직접 입력은 `다음`으로 확정 |
| 모든 기록 방식 → 1단계 · 확장 있는 본판 선택 | 선택한 본판(`다시 검색`), `함께 사용한 확장 (선택)`과 선택 수, 확장 칩(보유 → 위시·하고 싶은 → 직전 선택, 나머지는 `다른 확장 검색`), BGG 게임 ID·Powered by BGG | 다음 · 취소 | 다음은 선택한 확장을 유지한 채 2단계 이동, 선택 없이 다음이면 본판만 기록, `다시 검색`은 검색 결과로 복귀 |
| 모든 기록 방식 → `경기 기록 저장` 2단계 | 선택된 게임, 날짜·장소(새 장소는 직접 입력, 추천 목록은 이 계정 기록에 쓴 장소를 자주 쓴 순·같으면 최근 순으로 최대 30개, 그 뒤에 집·보드게임 카페·모임 장소·온라인 중 아직 안 쓴 것), 점수 기록일 때만 승리 조건 | 게임 다시 선택 · 저장하기 | 현재 점수판 또는 입력한 승패·팀·순위·협력 결과를 게임 정보와 함께 저장 |
| 로그인 여부 변경 | 두 저장 모달의 동일한 표시 규칙 | 이 기기에 저장 | 기존 계정별 저장 및 수동 동기화 대기 처리 유지 |

- 두 저장 모달에서 `점수 없이 기록` 옵션과 참여자·점수·승리 미리보기를 표시하지 않는다.
- 모든 기록 방식은 같은 `경기 기록 저장` 컴포넌트와 2단계 전환을 사용한다. 승패·팀·순위·협력 기록에는 승리 조건을 표시하지 않는다.
- 1단계에는 기록 정보 입력을, 2단계에는 검색 UI를 표시하지 않는다.
- 확장 칩은 누를 때마다 선택·해제한다. 같은 게임의 직전 기록에 쓴 확장을 미리 선택한다. 2단계의 선택한 게임 아래에 `+ 확장명`(2개 이상은 `+ 확장 N`) 배지를 표시한다.
- 1단계 하단의 `BGG 게임 ID 입력 수동으로 추가 (선택)`과 Powered by BGG는 확장 선택 중에도 유지한다.
- BGG 로고·게임 ID 입력·웹 검색을 표시하되 자체 게임 선택 시 웹 검색만 숨긴다.
- 두 저장 모달에서 `로그인해서 저장`과 저장 위치 안내는 숨긴다.
- 취소·닫기는 현재 입력 화면과 기존 저장 기록을 유지한다.

- 게임명과 날짜가 유효해야 한다.
- 저장 대상 플레이어가 1명 이상이어야 한다.
- 계정 전환 중이거나 저장 컨텍스트가 달라졌으면 저장을 중단한다.
- 로컬 저장 실패 시 화면 상태와 기존 기록을 원래대로 되돌린다.
- 로그인 상태에서도 기록 저장·수정·삭제는 먼저 로컬에만 반영하고 클라우드 대기열에 둔다.
- 로그인 직후나 네트워크 재연결만으로 클라우드 동기화를 시작하지 않는다.
- 클라우드 읽기·쓰기는 사용자가 설정의 `클라우드 동기화`를 누른 뒤에만 실행한다. BGG 사용자명·컬렉션·플레이 기록의 클라우드 받기도 이때 함께 한다(로그인만으로 받지 않음).
- BGG에서 받기(`내 정보 가져오기`)와 BGG로 보내기(`기록 내보내기`)는 해당 버튼을 누른 경우에만 실행한다. 자동 새 정보 확인은 하지 않는다.
- 로그인 중 받은 클라우드·BGG 데이터는 로그아웃해도 이 기기에 남고, 같은 ID의 데이터는 덮어쓴다.
- `내 정보 가져오기`로 받은 BGG 플레이 중 Score Counter가 내보낸 경기(메모의 `[ScoreCounter:기록ID]`)가 이 기기에 없으면 그 ID로 Score 기록을 되살린다(다른 기기에서 내보낸 기록을 클라우드 동기화 없이 받기 위한 보조 수단). 이미 있는 기록은 덮어쓰지 않고, 이 기기에서 삭제했거나 클라우드 동기화로 삭제를 받은 기록은 되살리지 않는다. 복원은 BGG 형식에 있는 정보(게임·날짜·장소·플레이어 이름·색·점수·승패·나 지정, 높은/낮은 점수 승리)만 쓰고, 협력 경기는 결과 미입력 협력 기록으로 되살린다(협력 결과·시나리오·난이도·미션·팀·순위·공동 점수·시나리오 레벨·확장은 없음). 되살린 기록은 다음 클라우드 동기화에서 클라우드에 원본이 있으면 원본으로 바뀌고, 없으면 클라우드에 올린다.
- 비로그인 상태에서도 기기 저장은 가능해야 한다.

- 기간 분석은 기간 요약·플레이 빈도 아래에 선택 기간 기준의 `방식별 나의 성적`, `어떤 게임을 했을까`(가족/파티(추상·테마 포함)·추리·협동·전략·스포츠·미분류 묶음별 서로 다른 게임 수, 게임당 한 묶음), `많이 플레이한 게임`(상위 8개)을 표시한다. 모든 카드 사이 간격은 같다(14px). `방식별 나의 성적`은 방식마다 판 수, 큰 승률(협력은 성공률·순위는 1위 비율), 승률 막대와 경기 인원(팀전은 팀 수)으로 본 기대 승률 세로선, 승리·무승부(협력은 성공·실패) 횟수, 기대 대비 차이 칩(높으면 초록·낮으면 빨강)을 보여 주고, 결과가 5판 이상인 방식 중 기대보다 가장 잘한 방식을 맨 위에 안내한다(판 수 많은 순).
- 기간 분석과 게임별 통계(게임 선택 목록의 횟수 포함)는 내가 플레이어로 참여한 기록(내 플레이어 지정 또는 내 닉네임 일치)만 집계한다. 내가 없는 기록은 저장·기록 목록에 그대로 남지만 통계에서는 플레이하지 않은 것으로 본다. 최근 기록은 전체 기록 기준이다.
- 게임별 통계 · 나의 기록은 기록 방식 선택 없이 그 게임에서 가장 많이 쓴 방식으로 보여 준다. 점수·결과를 적지 않은 판도 플레이 횟수에 넣고 승률에서는 뺀다(일부 사람만 점수를 적은 판은 적힌 점수만 평균·최고점에 넣는다).
- 게임별 통계와 기간 분석(기간 요약 바로 아래)은 `상대 전적` 카드를 표시한다: 그 기록에서 만난 이름 있는 상대를 함께한 판수 순으로 모두(8명까지, 나머지는 더 보기) 보여 주고 줄마다 함께한 판수·최근 날짜·승패무·승률을 쓴다. 승패는 나와 그 상대의 순위(없으면 승리 조건에 따른 점수, 승패 기록 방식은 승패)를 비교하며 비교할 수 없는 경기는 승률에서 뺀다. 3판 이상 비교한 상대 중 가장 많이 이긴·진 상대를 위에 강조한다. 협동 경기와 익명 상대는 제외한다. 같은 사람은 이긴 수가 진 수보다 많을 때만 '가장 많이 이긴 상대', 진 수가 더 많을 때만 '나를 가장 많이 이긴 상대'로 강조한다. 다인 경기는 나와 그 상대 중 앞선 사람을 승으로 센다. 경쟁 상대가 없고 협동 기록만 있으면 같은 카드에 `함께한 사람`(함께한 판수·성공 횟수·성공률)을 보여 준다. 기간 분석 카드는 숫자가 선택 기간 기준이며 줄을 누르면 전체 기간 전적이 열린다고 안내한다.
- `○○와의 전적` 화면(통계 탭 안): 전체 기간 기록으로 함께한 판수·내 승리·상대 승리·무승부와 비율 막대, 최근 5판 흐름(연승·연패), 게임별 전적(3판 이상이면 내가 우세·상대 우세·팽팽, 미만은 기록 적음), 함께한 협력 게임(같이 참여한 협동 경기의 성공률), 최근 대결 3개를 보여 준다. 기록의 플레이어 이름은 편집을 열므로 진입점으로 쓰지 않는다. 머리에 '전체 기간'을 표시한다. 연승·연패는 범위 안 전체 기록에서 세고 점은 최근 5판만 보인다. 최근 대결의 점수·순위가 없으면 승리·패배·무승부로 쓴다. 다인 경기가 있으면 앞선 순위를 승으로 셌다고 안내한다. 전체 게임 범위에서 2판 이상 비교한 게임이 2개 이상이면 `다음에 같이 해볼 게임`(팽팽한 승부·설욕전·자신 있는 게임, 서로 다른 게임 최대 3개)을 보여 준다. 경쟁 기록 없이 협동 기록만 있으면 협력 카드만 보여 준다.

설정 화면 새로고침 시 라우트 확인이 끝나기 전에 메인 화면을 잠시 노출하지 않는다.

로그인 완료, 앱 시작, 온라인 복귀는 동기화 실행 조건이 아니다. 동기화 실패는 사용자가 `클라우드 동기화`를 실행한 경우에만 표시하며, 실패해도 로컬 기록과 대기 변경을 유지한다.

클라우드와 BGG 가져오기는 현재 기기의 데이터와 ID·내용을 비교해 신규·변경·삭제된 항목만 로컬 및 클라우드 저장소에 반영한다. 내용이 같은 항목은 다시 저장하지 않는다.

### 기록에서 내 닉네임 지정하기

| 상태 | 액션 | 완료 결과 |
| --- | --- | --- |
| 비로그인 | 닉네임 지정·연결·해제 | 기기 게스트 설정만 저장 |
| 로그인 | 닉네임 지정·연결·해제 | 해당 계정의 기기 설정 저장, 클라우드 동기화 대기 |
| 같은 기기에서 재로그인·새로고침 | 계정 설정 복원 | 이전 대표·연결 닉네임 유지, 자동 클라우드 접근 없음 |
| 새 기기에서 로그인 후 클라우드 동기화 | 계정 설정 가져오기 | 기록과 함께 닉네임 설정 복원, 설정·통계에 반영 |
| 기기에 미동기화 닉네임 변경 있음 | 클라우드 동기화 | 기기의 변경을 우선 저장(전체 해제 포함) |
| 동기화 실패·진행 중 변경·계정 전환 | 기존 변경 보존 | 실패한 변경은 재시도 가능, 다른 계정에는 적용하지 않음 |

- 기존 기기에만 저장된 계정 닉네임도 다음 수동 동기화 때 업로드한다. 게스트나 다른 계정의 닉네임은 자동으로 합치지 않는다.
- 닉네임 동기화는 원본 기록의 이름·내 플레이어 플래그를 변경하지 않는다.

- 합치기·삭제는 개수와 범위를 안내하는 확인창을 사용한다. 취소하면 아무것도 변경하지 않는다.
- 합치기는 클라우드에 즉시 업로드하지 않는다. 계정에 이미 존재하거나 삭제 대기 중인 같은 ID는 덮어쓰거나 복원하지 않는다.
- 계정 저장 실패 시 로그인 전 기록과 기존 계정 기록을 보존한다. 계정 저장은 성공했지만 로그인 전 목록 정리에 실패하면 저장된 계정 사본을 유지하고 재시도를 안내한다.
- 확인창을 연 뒤 계정이나 로그인 전 기록이 변경되면 작업을 중단한다. 완료된 액션을 반복 실행해도 추가 저장·삭제하지 않는다.

### 데이터 가져오기 · BG Stats

- BG Stats 파일의 게임명·날짜·장소(locations의 이름)·플레이어·점수·승자를 가져온다. 메모·사진·컬렉션·도전과제는 가져오지 않는다.
- 같은 기록(같은 ID)은 중복으로 건너뛰되, 기존 기록에 장소가 없고 파일에 있으면 장소만 채운다(미리보기에 `장소 채움 N개`, 새 기록이 없어도 가져오기 가능).
- BG Stats 파일의 플레이별 BGG 플레이 번호(bggId)를 기록의 `bggPlayId`로 저장하고(다시 가져오면 기존 기록에도 채움), 이 번호의 BGG 플레이를 같은 경기로 본다. 번호가 없는 기록만 게임 BGG ID·날짜·참가자 이름·점수가 모두 같은 BGG 플레이(#bgstats)와 같은 경기로 본다. 이 기록은 BGG 내보내기에서 제외(`BG Stats가 이미 BGG에 올림 N개`)하고, 장소 관리 횟수도 한 번만 센다. BG Stats가 BGG에 줄여 올린 장소(`B.`)는 기록의 원래 장소로 대신한다.

- BG Stats 기록 중 이 앱이 올린 플레이가 없는 것은 BGG 내보내기 때 BG Stats 원본(bggPlayId)을 Score 기록 내용(원래 장소 포함)으로 업데이트하고 이후 그 원본을 업데이트 대상으로 쓴다. 그 날짜의 내 BGG 플레이에 원본이 없으면(지워진 경우) 새 플레이로 올린다.
- BGG로 기록 내보내기 때, BG Stats 원본이 지금 BGG에 있는데 Score가 따로 올린 플레이(업로드 기록이 있는 것)는 확인창에 개수를 알리고 BGG에서 삭제한 뒤 내보낸다. 원본이 BGG에 없으면(이미 삭제) Score가 올린 플레이를 남기고 평소처럼 업데이트한다. 워커는 이 앱이 올린 플레이 번호만 삭제한다.

### 장소 관리

| 상태 | 액션 | 완료 결과 |
| --- | --- | --- |
| 장소 목록 | 설정을 열 때 표시 | 이 계정 기록(비로그인은 이 기기, 로그인은 클라우드 동기화 포함)과 가져온 BGG 플레이(Score에서 내보낸 플레이는 기록과 중복으로 세지 않음)의 장소를 횟수·최근 날짜와 함께 많이 쓴 순으로 표시. 처음 20개, 나머지는 더 보기 |
| 기본 | 그 장소를 기본으로(다시 누르면 해제) | 새 기록 저장 때 장소 칸이 비어 있고 최근 입력 장소도 없으면 기본 장소를 채운다. 추천 목록 맨 위 |
| 숨기기 · 보이기 | 추천 목록에서 빼거나 되돌린다 | 기록은 바꾸지 않는다. 숨긴 장소는 목록 아래에 흐리게 표시 |

- BGG 플레이 장소는 `내 정보 가져오기`로 받은 플레이의 location 값을 쓴다.

## 9. 구현 불일치 추적

아래 항목은 이 문서 기준과 현재 구현이 다를 수 있으므로 관련 작업 시 우선 확인한다.

| 항목 | 기준 | 확인할 현재 구현 |
| --- | --- | --- |
| 메인 플레이어가 있는 점수 없는 기록 | 현재 플레이어 사용, 인원 선택 생략 | 인원을 2명으로 초기화하고 다시 선택하는지 확인 |
| 점수 없는 결과의 SAVE | 게임 정보 입력 액션 직접 호출 | 숨겨진 저장 버튼 `.click()` 위임 제거 |
| 빈 점수판 우측 상단 추가 | 랜덤 플레이어 한 명 즉시 추가 | 이름·색상 입력 화면이 열리지 않는지 확인 |
| 개인전·순위·협력 결과 입력 중 플레이어 추가 | 랜덤 플레이어 한 명 즉시 추가 | 이름·색상 입력 화면이 열리지 않는지 확인 |
| 팀전 결과 입력 중 플레이어 추가 | 이름·색상·소속 팀 입력 | 소속 팀 선택 화면이 유지되는지 확인 |

2026-10-20 동기화 점검에서 재현한 별도 개선 대상 (아직 미수정):

- `기기 기록 복구` 확인 콜백이 `sync()`를 직접 호출해 즉시 업로드한다. 동기화 CTA에서만 업로드한다는 정책과 불일치한다.
- 클라우드 읽기 중 `recordRevision`이 바뀌면 받은 서버 목록을 반영하지 않고 로컬 업로드만 수행한 뒤 `동기화됨`으로 표시한다.

### 새로고침 시 화면 복원

| 상태 | 초기 표시 | 복원 완료 |
| --- | --- | --- |
| 홈에서 점수/승패/팀전/순위/협력 기록 중 새로고침 | 중립적인 불러오기 상태 | 계정 확인과 해당 기록방식 복원을 마친 화면만 표시 |
| 게임·통계·설정에서 새로고침 | 요청한 탭 선택 상태와 불러오기 표시 | 같은 탭 유지, 홈의 진행 중 기록은 백그라운드 복원 |
| 모듈/계정 확인 지연 | 12초 뒤 다시 불러오기 CTA 제공 | 복원이 늦게 완료돼도 정상 화면으로 전환, 기록을 지우지 않음 |

- 기록 모듈은 모든 진입점에서 같은 URL로 가져와 한 번만 초기화한다.
- 복원 동작은 홈으로 강제 이동하거나 다른 탭 위에 작성 다이얼로그를 열지 않는다. 사용자가 새 기록을 시작하는 액션은 기존대로 홈으로 이동한다.
- 로그인·자동 동기화 정책과 저장 기록 형식은 변경하지 않는다.

## 10. 변경 요청 작성 형식

세밀한 수정 요청은 다음 다섯 줄이면 충분하다.

```text
대상 상태: 메인 점수판에 플레이어가 1명 이상
대상 CTA: 점수 없이 기록하기
변경 액션: 현재 플레이어를 그대로 사용하고 인원 선택 생략
유지 영역: 게임 선택 UI, 승패/순위 UI, 기존 점수판 데이터
완료 기준: 저장·취소·새로고침 후 원래 점수판 정상 복원
```

## 11. CTA 변경 체크리스트

- [ ] 상태별 노출 CTA가 표와 일치한다.
- [ ] 문구와 접근성 이름이 실제 액션과 일치한다.
- [ ] 동일 의도 CTA가 같은 액션 함수를 호출한다.
- [ ] 숨겨진 버튼 클릭 위임이 없다.
- [ ] 중복 클릭이 차단된다.
- [ ] 취소와 뒤로 가기의 데이터 보존 범위가 명확하다.
- [ ] 새로고침 후 작성 상태가 필요한 지점에서 복원된다.
- [ ] 기존 점수판과 저장 기록이 손상되지 않는다.
- [ ] 플레이어 0명, 1명 이상, 점수 없는 결과 입력 상태를 테스트했다.
