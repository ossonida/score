# Score Counter CTA 흐름 명세

이 문서는 버튼의 위치나 화면 모양이 아니라 **사용자 상태에 따른 CTA의 노출, 실행 액션, 완료 결과**를 정의한다. CTA 동작을 변경할 때는 구현보다 먼저 이 문서를 수정하고 합의한다.

## 1. 공통 규칙

1. 같은 사용자 의도를 가진 CTA는 같은 액션 함수를 호출한다.
2. CTA의 노출, 문구, 활성 상태는 하나의 상태 계산 결과로 결정한다.
3. 화면마다 같은 로직을 복제하거나 숨겨진 버튼의 `.click()`을 호출하지 않는다.
4. 액션 함수는 `진입 조건 확인 → 상태 생성 → 화면 전환 → 검증 → 완료/복구` 순서를 따른다.
5. 모달을 닫는 `취소`와 데이터를 폐기하는 `기록 취소`를 구분한다.
6. 새로고침 후 복원이 필요한 흐름은 임시 상태를 저장하고, 완료 또는 명시적 취소 시에만 제거한다.
7. CTA 수정 시 정상 완료뿐 아니라 뒤로 가기, 닫기, 새로고침, 중복 클릭을 함께 검증한다.
8. 하단 메뉴(홈·통계·게임·설정)는 다른 화면이면 그 화면으로 이동하고, 이미 보고 있는 화면의 버튼을 누르면 그 화면 맨 위로 스크롤한다.

## 2. CTA 상태 모델

CTA 판단에 필요한 최소 상태는 다음과 같다.

| 상태 | 의미 |
| --- | --- |
| `boardPlayers` | 현재 메인 점수판의 플레이어 목록 |
| `boardMode` | `score`, `win`, `rank`, `coop` 중 현재 기록 방식 |
| `activeSession` | 진행 중인 점수 게임 정보 |
| `scorelessDraft` | 작성 중인 점수 없는 기록 |
| `authState` | `guest`, `signed-in`, `checking` |
| `networkState` | `online`, `offline` |

버튼은 DOM 존재 여부로 상태를 추론하지 않고 위 상태에서 파생된 CTA 모델을 사용한다.

```text
resolveCtaState(appState)
  → visible
  → enabled
  → label
  → ariaLabel
  → action
```

## 3. 메인 점수판 CTA

### 3.0 시작 화면

첫 진입(이 기기에 저장된 점수판이 한 번도 없을 때)에는 랜덤 이름 플레이어 3명의 점수판을 바로 보여 준다(Figma A1). 플레이어를 모두 삭제하거나 초기 화면으로 돌아가면 빈 화면에 `플레이어를 추가하세요` 문구만 보여 주고, 추가는 우측 상단 여러 명 추가·한 명 추가로 한다. 홈에는 게임 먼저 선택 버튼이 없다. 게임을 골라 시작하는 것은 게임 탭에서 게임을 눌러 연 게임별 통계의 `플레이하기`로 한다. 점수가 모두 0이고 이름이 모두 자동 생성(랜덤) 그대로인 점수판은 `새 점수판`으로 보고 묻지 않고 바꾼다. 점수가 있거나 이름을 직접 정한 점수판이면 `현재 점수판을 비우고 {게임}(으)로 시작할까요?`(게임 이름 받침에 맞춰 으로/로) 확인 후 바꾸고, 결과 입력 중이면 시작하지 않고 안내한다.

| 현재 상태 | CTA | 실행 액션 | 완료 결과 |
| --- | --- | --- | --- |
| 첫 진입(저장된 점수판 없음) | 없음(자동) | 랜덤 플레이어 3명 생성 | 3명 점수판 표시. 게임은 SAVE 때 선택 |
| 플레이어 0명(모두 삭제·초기 화면으로) | 우측 상단 여러 명 추가 | 빈 화면에 `플레이어를 추가하세요` | 추가하면 점수판 시작 |
| 게임 탭 → 게임 → 게임별 통계 | 우측 하단 `플레이하기`(게임 먼저 선택의 유일한 진입점) | 게임 시작 흐름 열기 | 흐름 완료 시 점수판을 고른 참가자로 바꾸고 선택한 방식의 입력 화면 시작 |
| 점수가 있는 점수판 또는 결과 초안 있음 | - | - | 진행 중인 점수판·결과 입력 표시 |

#### 게임 먼저 선택 흐름(게임별 통계 `플레이하기`)

```text
게임 탭 → 게임 → 게임별 통계 `플레이하기`(게임이 이미 정해져 게임 검색 단계 없음)
→ 1. 참가자: 여러 명 추가와 같은 창(제목 `여러 명 추가`, 기존 플레이어 선택 + 랜덤 이름으로 추가할 인원, 합이 참가 인원)
→ 2. 기록 방식: 고르지 않고 이 게임에서 가장 많이 쓴 방식으로 자동 시작(기록이 없으면 아래 추천 방식, 마이티면 마이티 기록)
→ 3. 입력 시작: 점수 → 점수판(고른 게임의 점수 세션), 승패·순위·협력 → 기존 결과 입력 화면(4.4)
→ SAVE → 저장창은 게임이 선택된 상태로 날짜·장소 단계부터 시작
```

| 단계 | 노출 CTA | 기본값 | 닫기·취소 |
| --- | --- | --- | --- |
| 1. 참가자 | 제목 `여러 명 추가`, `확인` (합 1명 이상) | 랜덤 0명(기존 플레이어를 고르거나 +로 인원 지정) | 게임 시작 취소, 기존 점수판 유지 |
| 2. 기록 방식 | 없음(자동) | 가장 많이 쓴 방식, 기록이 없으면 추천 방식 | - |
| 3. 입력 화면 | 기존 화면의 CTA, 위쪽에 고른 게임 표시(점수판 기록 상태 문구·결과 화면 제목) | - | 기존 `기록 취소`·리셋 규칙(4.5) |

추천 방식 (새 저장 데이터 없이 계산):

1. 같은 게임의 가장 최근 기록 방식(점수 → 점수, 개인전·팀전 → 승패, 순위 → 순위, 협력 → 협력).
2. 기록이 없고 BGG 정보가 협력 게임이면 협력.
3. 기록이 없고 BGG 정보가 추리(deduction) 게임이거나 이름이 마피아류(마피아·늑대인간·스파이폴·아발론·레지스탕스·시계탑/Clocktower 등)이면 승패.
4. 그 밖에는 점수.

고정 조건:

- 고른 게임은 점수 세션 또는 결과 초안에 함께 저장해 새로고침 후에도 복원한다.
- 확장은 SAVE 저장창에서 고른다(1단계에서는 묻지 않는다).
- 점수판이나 결과 입력(기록 방식 변경 후 포함)이 진행 중일 때 다른 게임의 `플레이하기`를 누르면 확인창(`현재 점수판을 비우고 …` / `입력 중인 결과를 취소하고 …`)을 띄우고, 확인하면 기존 진행을 정리한 뒤 새 게임으로 1단계를 연다. 취소하면 그대로 둔다.
- 게임이 이미 정해진 점수 세션·결과 초안의 SAVE 저장창은 2단계(날짜·장소)부터 연다. `게임 다시 선택`으로 1단계에 갈 수 있다.
- 저장 후에도 고른 게임을 유지한다(같은 게임을 이어서 기록). 플레이어 전체 리셋·`기록 취소`·마지막 플레이어 삭제로 입력을 끝내면 고른 게임도 지우고 시작 화면으로 돌아간다.
- `기록 방식 변경`은 지금처럼 쓸 수 있고 결과 기록끼리 바꿀 때 고른 게임은 유지한다.
- 홈에서 바로 시작한 점수판은 지금과 같다(SAVE 때 게임 선택).
- 역할 게임 방식과 연속 판(라운드제)은 다음 단계에서 기록 방식으로 추가한다.

### 3.1 플레이어 추가

| 현재 상태 | CTA 위치 | 노출 문구/이름 | 실행 액션 | 완료 결과 |
| --- | --- | --- | --- | --- |
| 점수 기록 | 우측 상단 셋째 | 여러 명 추가 | 여러 명 추가 열기 | 기존 플레이어와 점수 유지하고 고른 인원 추가 |
| 플레이어 1명 이상 | 우측 상단 | 랜덤 플레이어 한 명 추가 | 이름·색상 입력 없이 랜덤 플레이어 즉시 추가 | 기존 점수와 플레이어를 유지하고 1명 추가 |
| 개인전·순위·협력 결과 입력 중 | 우측 상단 | 랜덤 플레이어 한 명 추가 | 이름·색상 입력 없이 현재 결과에 랜덤 플레이어 즉시 추가 | 현재 결과 목록에 1명 추가 |
| 팀전 결과 입력 중 | 우측 상단 | 플레이어 한 명 추가 | 한 명 추가 창에서 이름·색상·소속 팀 지정 | 선택한 팀에 1명 추가 |

고정 조건:

- 우측 상단 툴바 순서는 `(턴 타이머) · (점수 초기화) · 여러 명 추가 또는 한 명 추가 · ⋮ 더보기`이다(아이콘만, 배경·테두리 없음). 플레이어가 0명이면 `여러 명 추가`, 1명 이상이면 같은 자리에 `한 명 추가`(플레이어+ 아이콘, 아래 한 명 추가 CTA)만 보인다(2026-11-06, 우측 하단 플로팅 + 버튼은 두지 않음). 아이콘은 모든 폭에서 44px을 유지한다. `⋮`(세로 점 3개)는 아래로 펼치는 메뉴로 `기록방식 변경`, `삭제`(빨강, 플레이어 전체 지우기, 플레이어가 있을 때만)를 이 순서로 담는다(아이콘 22px 칸 고정, 글자와 세로줄 맞춤, 키보드로 열 때만 첫 항목에 포커스). 메뉴 항목을 누르면 메뉴를 닫고 그 액션을 실행한다. 바깥 누르기·Esc·다시 `⋮`로 닫는다. 항목이 하나도 없으면 `⋮`을 숨긴다(2026-11-05, 좁은 화면에서 아이콘이 작아지는 문제로 Figma A1·A3·A4 툴바에서 변경). 여러 명 추가와 한 명 추가는 파란 버튼. 점수 초기화 아이콘은 Figma Toolbar/Reset Scores(24px, 화살표 20px)를 따른다.
- 점수판 자동 저장이 실패하면(브라우저 저장 공간 사용 불가) 점수판 아래 안내 줄에 `브라우저 저장 공간을 사용할 수 없어 점수가 저장되지 않습니다.`를 보여 주고, 다음 자동 저장이 성공하면 지운다.
- 우측 상단 한 명 추가 CTA는 팀 선택이 필요한 팀전 결과에서만 입력창을 열고, 나머지 화면에서는 랜덤 플레이어를 즉시 추가한다.
- 여러 명 추가 화면에서 선택한 기존 플레이어와 자동 생성 인원의 합이 실제 추가 인원이다.
- 팀전 한 명 추가를 취소하면 기존 결과 상태를 변경하지 않는다.
- 마이티 기록은 4~6명이다. 6명이면 여러 명 추가·한 명 추가를 비활성으로 두고, 여러 명 추가로 6명을 넘기면 `마이티는 6명까지 기록할 수 있습니다.`로 막는다.
- 결과 입력 중 `여러 명 추가`로 넣은 사람은 현재 결과에 바로 보인다: 팀전은 인원이 가장 적은 팀, 역할전·추리는 나머지 진영(시민·탐정 쪽), 순위는 맨 뒤 순위, 그 밖은 결과 미입력.

### 3.2 개별 플레이어 삭제

| 진입 방식 | 실행 액션 | 확인 | 완료 결과 |
| --- | --- | --- | --- |
| 플레이어 카드를 왼쪽으로 밀기 | 해당 플레이어 즉시 삭제 | 묻지 않음 | 점수 기록은 이름·점수 삭제, 결과 기록은 이름·결과 삭제 |
| 플레이어 이름 → 수정창 → 삭제 | 해당 플레이어 삭제 | 확인창 표시 | 확인 시에만 삭제 |

- 어떤 기록 방식에서도 마지막 플레이어까지 삭제할 수 있다. 마지막 플레이어가 삭제되면 작성 중인 결과 초안을 종료하고 `플레이어를 추가하세요` 빈 화면(3.0)을 보여 준다.
- 순위 기록에서 삭제하면 남은 플레이어의 순위를 즉시 다시 계산한다.
- 결과 기록에서 삭제한 플레이어는 기록 방식을 다시 변경해도 복원하지 않는다. 점수 기록으로 돌아갈 때도 남은 플레이어의 기존 점수만 복원한다.
- 왼쪽으로 미는 동안 카드 아래의 빨간 삭제 영역은 이동 거리에 맞춰 끝까지 부드럽게 드러난다.
- 두 진입 방식은 같은 삭제 상태 갱신 함수를 사용하고 확인 여부만 다르게 처리한다.

### 3.3 점수 초기화

| 진입 조건 | 확인 문구 | 완료 | 취소 |
| --- | --- | --- | --- |
| 점수 기록 모드이고 0이 아닌 점수가 하나 이상(툴바 둘째 칸, 아니면 숨김) | 모든 플레이어의 점수를 0으로 초기화 | 이름·색상·순서는 유지하고 점수만 0 | 변경 없음 |

점수 없는 결과 입력 중에는 노출하지 않는다.

### 3.4 플레이어 전체 지우기

| 진입 조건 | 확인 문구 | 완료 | 취소 |
| --- | --- | --- | --- |
| 플레이어가 한 명 이상이면 늘 우측 상단 `⋮` 메뉴의 `삭제`(휴지통 아이콘). 점수 기록·결과 입력 모두. 플레이어가 없을 때만 숨김. 한 명씩은 카드 밀어서 삭제 | 플레이어 리셋: 추가된 플레이어와 점수를 모두 삭제할까요? | 플레이어·점수를 모두 지우고 빈 화면(`플레이어를 추가하세요`). 결과 입력 중이면 임시 결과도 끝내고 빈 점수판으로 전환. 저장한 기록은 유지 | 변경 없음 |

서로 다른 두 액션을 같은 핸들러에서 분기하더라도 사용자 문구와 확인 내용은 현재 모드에 맞아야 한다.

### 3.5 게임 종료 / SAVE

기록 방식이 점수·승패·순위·협력 중 하나로 변경되어도 우측 상단 툴바의 순서와 사용자 의도는 유지한다. `SAVE`는 툴바가 아니라 플레이어 카드 바로 아래에 카드 폭 전체 버튼(높이 48px, 어두운 면·얇은 테두리·파란 글자)으로 둔다(2026-11-05 카드 폭으로 변경, 2026-11-06 파란 채움이 너무 튀어 차분하게). 저장할 수 없는 상태(비활성)는 회색. 단, 점수 초기화는 점수 기록 모드에서만 노출한다. `SAVE`는 현재 방식의 기록 저장을 진행하고, 플레이어 추가는 현재 결과에 한 명을 추가한다. 버튼 문구와 접근성 이름도 기록 방식 전환만으로 바꾸지 않는다.

| 현재 상태 | CTA | 활성 조건 | 실행 액션 | 완료 결과 |
| --- | --- | --- | --- | --- |
| 점수 게임 진행 중 | SAVE | 플레이어 1명 이상 | 게임·날짜·장소 입력 열기 | 현재 점수판을 유지한 채 기록 저장 진행 |
| 점수 없는 승패 입력 중 | SAVE | 모든 플레이어 결과 입력 | 게임·날짜·장소 입력 열기 | 결과와 임시 상태 유지 |
| 점수 없는 순위 입력 중 | SAVE | 1위부터 모든 순위 유효 | 게임·날짜·장소 입력 열기 | 결과와 임시 상태 유지 |

구현 조건:

- `SAVE`는 기록 방식과 관계없이 같은 문구·위치(카드 아래 전체 폭)·색상을 유지하며 현재 모드에 맞는 저장 액션을 직접 호출한다.
- 숨겨진 하단 저장 버튼을 대신 클릭하지 않는다.
- 저장 중에는 중복 클릭을 막고 성공 또는 실패 상태를 명확히 표시한다.
- 저장 완료는 입력 화면을 종료하는 액션이 아니다. 점수·개인전 승패·팀전 승패·순위 기록 모두 현재 방식과 플레이어, 점수·결과를 유지한다.

| 저장 상태 | 노출 CTA | 실행 액션 및 완료 결과 |
| --- | --- | --- |
| 점수 입력 후 게임 정보 저장 성공 | 기존 SAVE·플레이어 편집·리셋 | 기록 사본 저장, 현재 점수판과 점수 유지. 화면 위쪽 가운데에 흰 카드(파란 체크 + `점수가 기록되었습니다.`)를 3.5초 표시(Figma A7-1) |
| 개인전·팀전 승패 또는 순위 입력 후 게임 정보 저장 성공 | 기존 SAVE·기록 방식 변경·리셋 | 기록 사본 저장, 현재 결과 화면과 입력·게임 정보 유지 |
| 저장 완료 후 새로고침 | 같은 기록 방식의 CTA | 동일한 플레이어·팀 구성·승패·순위 복원 |
| 저장 실패 또는 저장창 닫기 | 현재 입력 화면의 CTA | 현재 내용과 기존 저장 기록 유지 |
| 명시적인 플레이어 삭제·리셋·기록 취소 | 기존 삭제·취소 액션 | 해당 입력만 정리, 이미 저장한 기록은 유지 |

### 3.5 기록 방식 변경

`기록 방식 변경`은 우측 상단 `⋮` 메뉴의 첫 항목(문구 `기록방식 변경`)(Toolbar/recordModeChange 아이콘 + 문구)이다. 점수 기록과 결과 입력(승패·팀전·역할전·추리·순위·협력·마이티) 모두 같은 항목을 쓰고, 결과 입력 하단의 `기록 방식 변경` 버튼은 두지 않는다. 하단 텍스트 버튼과 안내 문구(이름은 수정 · 점수는 직접 입력 · 왼쪽으로 밀면 삭제)는 두지 않는다.

| 현재 기록 방식 | 선택창에 노출할 CTA |
| --- | --- |
| 점수 기록 | 승패 기록 · 순위 기록 · 협력 기록 · 마이티 기록 |
| 승패 기록 | 승패 기록(개인전·팀전 전환) · 점수 기록 · 순위 기록 · 협력 기록 · 마이티 기록 |
| 순위 기록 | 점수 기록 · 승패 기록 · 협력 기록 · 마이티 기록 |
| 협력 기록(4가지 방식 중 하나) | 점수 기록 · 승패 기록 · 순위 기록 · 협력 기록(다른 협력 방식으로 전환) · 마이티 기록 |
| 마이티 기록 | 점수 기록 · 승패 기록 · 순위 기록 · 협력 기록 |

`협력 기록`을 누르면 `협력 기록 방식` 단계로 이동한다.

| 협력 방식 | 입력 | 저장 활성 조건 | 저장 값 |
| --- | --- | --- | --- |
| 성공·실패·점수형 | 경기 전체 성공·실패, 공동 점수(선택) | 결과 선택, 점수 유효 | `cooperativeResult`, `sharedScore`(선택) |
| 미션형 | 아래 '협력 미션 기록' 표 | 시도 1회 이상 | `missionAttempts` |
| 난이도형 | 난이도 선택(게임별 목록, 없으면 입문·보통·어려움·최고 / 판데믹 입문·보통·영웅·전설) + 성공·실패 | 난이도와 결과 선택 | `cooperativeResult`, `difficulty` |
| 캠페인형 | 시나리오 번호(‹ ›, 1~999) + 시나리오 레벨(선택, 0~7, 누른 레벨을 다시 누르면 해제) + 성공·실패, 같은 게임·시나리오 시도 횟수는 기록에서 자동 계산 | 결과 선택 | `cooperativeResult`, `scenario`, `scenarioLevel`(선택) |

- 선택 단계에는 현재 사용 중인 협력 방식을 빼고 노출하며, `기록 방식으로`는 이전 단계로 돌아가고 입력은 유지한다.
- 최근 협력 기록이 있으면 게임별 최신 1개를 `게임 · 방식 · 마지막 값` 칩(최대 3개)으로 보여 주고, 누르면 그 게임·방식·난이도(캠페인은 갈래로 열리는 게임이 많아 마지막 시나리오 번호와 레벨을 그대로, 미션은 다음 미션)를 미리 선택한 채 시작한다.
- 기존 기록은 변환하지 않는다. 미션 시도가 있으면 미션형, `scenario`가 있으면 캠페인형, `difficulty`가 있으면 난이도형, 나머지 협력 기록은 성공·실패·점수형으로 읽는다.

고정 조건:

- 현재 사용 중인 기록 방식은 선택창에 중복 노출하지 않는다.
- `기록 방식 변경`은 모든 기록 방식에서 같은 선택창과 같은 전환 함수를 사용한다.
- 선택창을 닫으면 현재 기록 방식과 입력 내용을 그대로 유지한다.
- 점수 기록에서 다른 방식으로 이동할 때 현재 점수판을 스냅샷으로 보존한다.
- 승패·순위·협력 기록에서 점수 기록으로 돌아오면 삭제되지 않은 플레이어의 전환 전 점수를 복원한다.
- 승패·순위 사이를 전환할 때 참가자·이름·색상·추가 플레이어는 유지하고 방식별 결과만 초기화한다.
- 결과 입력 중 삭제한 참가자는 이후 어떤 기록 방식으로 전환해도 다시 추가하지 않는다.
- 결과 입력 중 플레이어를 추가하거나 이름·색상을 수정하면 점수 기록의 기준 명단에도 즉시 반영한다. 새 플레이어가 점수 기록으로 돌아갈 때의 초기 점수는 0점이다.
- 협력 기록은 경기 전체의 성공·실패와 선택적인 공동 점수를 입력한다. 상세 저장·집계 기준은 7절을 따른다.
- 협력 미션 기록은 협력 기록과 같은 `coop` 결과 화면을 쓰되 `경기 전체 결과` 대신 `미션 진행` 영역을 보여준다. 공동 점수는 받지 않는다.

#### 협력 미션 기록 (플레이하며 기록)

| CTA | 조건 | 실행 | 보존 조건 |
| --- | --- | --- | --- |
| 이전 미션 `‹` / 다음 미션 `›` | 미션 1~999 범위 | 현재 도전 미션 번호만 변경 | 이미 기록한 시도는 유지 |
| 이어하기 칩 `게임 · 미션 N부터` | 시도 0회이고 이전 미션 기록이 있을 때 | 현재 미션을 N으로, 저장할 게임을 그 게임으로 설정 | 첫 시도 후 칩 숨김 |
| 실패 | 항상 | 현재 미션 실패 1회 추가, 같은 미션 유지 | 임시 기록에 즉시 보존 |
| 성공 | 항상 | 현재 미션 성공 1회 추가 후 다음 미션으로 이동 | 임시 기록에 즉시 보존 |
| 되돌리기 | 시도 1회 이상 | 마지막 시도 1개 삭제, 그 시도의 미션으로 복귀 | 이전 시도 유지 |
| 하단 `끝내고 저장 · 시도 N · 클리어 M` | 시도 1회 이상 | 기존 저장 대화상자(게임·날짜·장소) 열기 | 시도 0회면 비활성 `미션 결과 선택` |

- 한 세션(저장 1회)은 기록 1개, 플레이 1판이다. 시도 내역은 `missionAttempts`로 저장한다.
- 세션 결과(`cooperativeResult`)는 미션을 하나라도 성공했으면 성공, 아니면 실패로 자동 결정하며 기록 수정에서 바꾸지 않는다.
- 새로고침·앱 재시작 후에도 시도 내역과 현재 미션을 복원한다.
- 새로고침 후에는 확정된 현재 기록 방식과 해당 임시 상태를 복원한다.

### 3.6 턴 타이머

점수판 기록 화면(점수·결과 입력 모두)에 턴별 실시간 타이머를 더한다. 점수판에는 우측 상단 툴바 첫 칸의 타이머 아이콘만 추가하고, 플레이어별 시간·현재 턴·다음 플레이어·턴 순서·설정은 모두 아이콘으로 여는 전체 화면(`턴 타이머 관리`) 안에만 둔다. 전체 화면은 위 뒤로가기(닫기, Esc 포함)와 스크롤 영역(라운드·다음 예정·전체 경과 → 현재 플레이어 카드(이름·상태 · 누적 사용 시간 · 이번 턴, 카드 아래쪽에 주 CTA와 되돌리기 아이콘) → 턴 순서 → `일시정지 · 설정` 줄 → 설정 펼침)으로 구성한다(Figma 189:441). 저장됨 상태만 카드에 CTA가 없고 화면 아래 고정 영역에 `새 타이머`를 둔다. 닫아도 타이머는 계속 측정한다. 기존 툴바 버튼의 순서·위치·동작, 점수 `+ / −`, 순위, 점수 미입력 표시는 바꾸지 않는다. 플레이어가 없으면 아이콘을 숨긴다.

| 아이콘 상태 | 표시 |
| --- | --- |
| 타이머 미사용·대기·라운드 종료·저장됨 | 일반 아이콘 |
| 개인 턴 측정 중·공용 시간 | 아이콘 오른쪽 위 초록 점 |
| 일시정지 | 아이콘 오른쪽 위 노란 점 |

화면의 주 CTA는 상태 하나(`status`)에서 결정한다.

| 상태 | 주 CTA(카드 안) | 되돌리기 아이콘 | `일시정지` |
| --- | --- | --- | --- |
| 시작 전(`idle`) | `{이름} 턴 시작`: 지정한 플레이어(선플레이어, 없으면 순서 첫 사람) 측정 시작 | — | 비활성 |
| 측정 중(`running`) | `{이름} 턴 종료`(체크 아이콘): 현재 턴 확정 → 다음 예정 플레이어로. 자동 시작이면 바로 측정, 수동이면 시작 대기 | 되돌릴 전환이 있을 때 | 활성 |
| 시작 대기(`waiting`) | `{이름} 턴 시작` | 되돌릴 전환이 있을 때 | 활성 |
| 일시정지(`paused`) | `타이머 재개`: 멈춘 상태(측정 중이던 플레이어 포함)로 복귀 | — | 비활성 |
| 공용 시간(`shared`, 이전 버전에서 시작한 경우만) | `타이머 재개`: 공용 시간 전 상태로 복귀 | — | 활성 |
| 라운드 종료(`roundEnd`, 모두 패스) | `다음 라운드`: 라운드 +1, 패스 초기화, 시작 대기(자동 측정하지 않음) | 되돌릴 전환이 있을 때 | 활성 |
| 저장됨(`ended`, SAVE로 기록 저장 후) | 카드엔 없음. 아래 고정 `새 타이머`: 확인 후 시간·이력 초기화(순서·자동 시작 설정 유지) | — | 숨김(`설정`만 전체 폭) |

플레이어 목록 바로 아래, `일시정지`·`설정` 줄 위에 전체 폭 `다음 라운드` 버튼을 둔다(저장됨 외 항상 보임, 측정 중·시작 대기·라운드 종료에서 활성: 진행 중인 턴을 확정하고 라운드 +1, 패스 초기화, 선플레이어(없으면 순서 첫 사람) 시작 대기. 모두 패스하지 않아도 넘어가며 되돌리기 가능). `설정`은 아래 설정 영역을 펼치고 접는다(처음엔 접힘). 공용 시간 시작 버튼과 줄별 `다음`(다음 차례 1회 지정) 칩은 Figma 수정(2026-11-04)에 따라 화면에서 뺐다.

플레이어 목록(턴 순서 순):

- 깃발: 선플레이어 지정(한 명). 시작 전이면 최초 선플레이어도 함께 바뀐다. 순서는 자동으로 바꾸지 않는다.
- 이름 줄: 그 플레이어로 직접 턴 전환. 측정 중이던 다른 플레이어 턴은 확정 후 전환하고, 자동 시작이면 바로 측정·수동이면 시작 대기. 측정 중인 같은 플레이어를 다시 누르면 아무 일도 없다(중복 턴 방지). 라운드 종료 중에는 다음 라운드 시작 플레이어 지정.
- `패스`: 이번 라운드 자동 진행에서 제외(다시 누르면 취소). 측정 중인 본인이 패스하면 그 턴을 확정하고 다음으로. 모두 패스하면 라운드 종료.
- 줄 구성: 깃발 · 이름(이름 옆에 진행 중·다음·패스 같은 상태, 아래에 누적 시간) · `패스` · 핸들. 목록 머리 오른쪽 안내는 `길게 눌러 순서 변경`.
- 오른쪽 핸들(점 6개): 순위 기록과 같은 길게 눌러 끌기(키보드 ↑↓). 턴 순서만 바뀌고 점수판 순위·플레이어 순서와 진행 중인 시간은 그대로이며 다음 턴부터 적용.

설정(`설정` 버튼으로 펼침), 위에서부터:

1. **턴 종료 후 다음 플레이어**: `자동 시작` 체크(앞 플레이어가 턴 종료를 누르면 바로 측정, 기본 끔, 다음 턴부터 적용).
2. **제한 시간 방식**(라디오, 기본 제한 없음): `제한 없음`(사용 시간만 누적) · `게임 전체 제한 시간`(1인당 시간을 여러 턴에 걸쳐 차감) · `매 턴 제한 시간`(턴마다 새로 부여).
3. 제한이 있을 때만: **1인당 매 턴 제한 시간 (분)**(게임 전체면 `1인당 게임 전체 제한 시간 (분)`) 숫자 입력(1~999, 기본 3) + 빠른 선택 `1분 · 3분 · 5분 · 10분`, **시간 초과 시**(라디오, 기본 경고) `경고 표시 후 계속 측정` · `제한 시간 도달 시 개인 타이머 정지`. **음성 안내**(토글, 기본 끔, 기기 타이머에만 저장): 측정 중인 플레이어의 남은 시간(매 턴이면 이번 턴, 게임 전체면 그 플레이어 남은 전체)이 1분·30초·10초가 되면 "1분 남았습니다"·"30초 남았습니다"·"10초 남았습니다", 5초부터 "5, 4, 3, 2, 1", 0초에 "시간이 종료되었습니다"를 기기 한국어 음성으로 읽는다. 제한 시간보다 크거나 같은 안내는 건너뛴다. 턴은 자동으로 끝내지 않는다(턴 종료는 직접). 타이머 화면이 닫혀 있어도 안내하며, 새로고침·되돌리기·턴 전환 뒤 이미 지난 안내는 다시 읽지 않는다. 켤 때 "음성 안내를 켰습니다"로 확인(아이폰 소리 허용도 이때·턴 시작 때 연다). 음성 합성을 지원하지 않는 브라우저에선 비활성과 안내 문구.
4. **이번 라운드 패스**: 플레이어별 토글(줄의 `패스`와 같은 동작). `다음 라운드` 버튼은 목록 아래 `일시정지`·`설정` 줄 위에 있다.
5. 플레이어 시간 수정(진행 중이면 정산 후 적용, 음수 불가, 전후 값 기록), 타이머 초기화(확인).

제한 시간 표시: 제한이 있으면 현재 플레이어 카드의 큰 숫자가 **남은 시간**(매 턴 제한이면 이번 턴 남은 시간, 아직 턴이 없으면 제한 시간 전체)이 되고 아래 줄에 누적·이번 턴 시간을 보인다. 남은 시간이 0이 되면 경고 방식은 상태를 `시간 초과`(빨강)로 바꾸고 `+초과 시간`을 계속 세며, 정지 방식은 그 플레이어 시간을 제한 시간에서 멈추고(전체 경과는 계속) `시간 종료`를 표시한다. 어느 방식이든 턴 종료는 직접 누른다. 시간이 넘은 동안 툴바 아이콘 점은 빨강. 제한 설정은 기기 타이머에만 두고 기록(`turnTimer`)에는 넣지 않는다. 설정을 바꾸면 그때까지의 시간을 정산한 뒤 적용한다.

- 시간은 기준 시각(ms)으로 계산하고 화면은 1초 단위로만 표시한다. 시트를 닫거나 점수를 입력하거나 앱을 다시 열어도 계속 계산된다(`score.turnTimer.v1`, 기기 저장).
- 되돌리기(주 CTA 오른쪽 아이콘)는 직전 턴 전환(턴 시작·종료·직접 선택·패스·다음 라운드)을 취소한다. 그 사이 자동 시작된 다음 플레이어 시간은 버리고 이전 플레이어는 원래 시작 시각부터 이어 측정한다(일시정지했던 시간 제외). 일시정지·공용 시간 중에는 비활성.
- SAVE로 기록을 저장하면 타이머를 멈추고 기록에 `turnTimer`(전체 경과·공용 시간·라운드·최초/현재 선플레이어·플레이어 ID별 시간·턴 이력·수정/취소 이력)를 함께 저장한다. 타이머를 쓰지 않은 기록에는 넣지 않는다. 클라우드에는 기존 기록 동기화로 올라간다. 진행 중인 타이머 자체는 점수판처럼 기기에만 둔다.
- 통계 기록 목록의 기록 카드에서 타이머를 쓴 기록에만 플레이 시간과 플레이어별 소요 시간(펼치면 턴별 이력)을 보여 준다.

## 4. 점수 없는 게임 기록 CTA

### 4.1 진입 경로

| 진입 상태 | 노출 CTA | 참가자 처리 | 다음 단계 |
| --- | --- | --- | --- |
| 메인 플레이어 0명(빈 화면) | 기록 방식 CTA 없음 | 우측 상단 여러 명·한 명 추가 | 점수 기록 시작 |
| 메인 플레이어 1명 이상 | 기록 방식 변경 | 현재 점수판 플레이어를 그대로 사용 | 기록 방식 선택 → 결과 입력 |

점수 없는 게임은 게임 탭 → 게임별 통계의 `플레이하기`(3.0)로 바로 시작하거나, 플레이어를 먼저 추가한 뒤 기록 방식을 변경한다. 게임을 정하고 시작한 점수판에서 기록 방식을 바꾸면 그 게임·날짜·장소를 이어받아, 결과 화면의 SAVE는 저장창 2단계(날짜·장소)부터 연다.

### 4.2 플레이어 0명일 때

```text
빈 화면(플레이어를 추가하세요)
→ 우측 상단 여러 명 추가 · 한 명 추가
→ 점수 기록 화면
→ 우측 상단 기록 방식 변경
→ 승패 · 추리 · 순위 · 협력 · 마이티 중 선택
```

### 4.3 플레이어 1명 이상일 때

```text
기록 방식 변경
→ 현재 점수판 플레이어 스냅샷 생성
→ 현재 방식을 제외한 3개 방식 중 선택
→ 현재 플레이어 결과 입력
→ SAVE
→ 게임·날짜·장소 선택
→ 기록 저장
→ 기록 저장 후 현재 기록 방식과 입력한 결과 유지
```

고정 조건:

- 점수 없는 기록을 시작해도 기존 점수판의 이름, 색상, 점수와 진행 세션을 덮어쓰지 않는다.
- 결과 입력 화면에서 추가한 플레이어는 점수 없는 기록에만 반영한다.
- 이름 수정도 임시 결과 목록에만 반영하고 기존 점수판 이름을 임의로 바꾸지 않는다.
- 새로고침하면 작성 중인 단계와 결과를 복원한다.
- 저장 성공 후에도 현재 결과와 선택한 게임 정보를 초안에 유지한다. 명시적인 `기록 취소`, 플레이어 리셋·전체 삭제, 점수 기록으로의 전환에서 기존 정리 동작을 실행한다.
- 저장된 기록은 입력 화면의 사본이다. 저장 후 입력을 수정하거나 삭제해도 이미 저장한 기록은 바뀌지 않는다.

### 4.4 기록 방식 선택

| CTA | 결과 UI | 완료 조건 |
| --- | --- | --- |
| 승패 기록 | 개인전·팀전 선택 | 선택한 경기 형태의 구성 단계로 이동 |
| 개인전 | 플레이어별 승리·무승부·패배 선택 | 모든 플레이어가 하나의 결과를 가짐 |
| 팀전 | 2~4팀 구성 후 팀별 승리·무승부·패배 선택 | 모든 팀이 하나의 결과를 가지며 모든 플레이어가 팀에 배정됨 |
| 순위 기록 | 추가 순서대로 1위부터 표시, 손잡이 드래그로 재정렬 | 모든 플레이어가 중복 없는 연속 순위를 가짐 |
| 점수 기록 | 기존 점수판으로 복귀 | 전환 전 이름·색상·점수·순서 복원 |
| 협력 기록 | 협력 방식 선택 후 방식별 입력(3.5 협력 방식 표), 참가자 | 방식별 저장 활성 조건 충족 시 저장 활성 |
| 마이티 기록 | 판마다 주공(플레이어 1명)·공약(13~20, − +)·기루다(♠♥♦♣ 또는 노기루다 ×2)·프렌드(주공 외 1명 또는 노프렌드) 선택 후 `실패`/`성공`, 플레이어 카드에 누적 점수와 지금 고른 주공·프렌드 표시, `↶ 되돌리기`는 마지막 판 취소 | 4~6명일 때 시작 가능. 성공·실패는 주공·기루다·프렌드를 모두 고르면 활성. 저장은 판 1개 이상 |
| 기록 방식 변경 | 현재 방식을 제외한 3개 CTA 표시 | 선택 전까지 현재 입력 내용 유지 |

마이티 판 점수(Figma 51:441 가정 규칙): 기본 = (공약 − 12) × (노기루다면 2), 성공 +, 실패 −. 프렌드 1배, 야당 각 반대 부호 1배, 주공은 합계가 0이 되도록 (야당 수 − 1)배(5인 2배), 노프렌드면 주공 야당 수배(5인 4배). 판을 기록하면 주공·프렌드·기루다 선택을 비우고 공약은 13으로 돌린다. 저장은 누적 점수를 플레이어 점수로 하는 점수 기록(높은 점수 승리)이며 판별 내역은 기록의 선택 필드 `mightyRounds`(주공·프렌드·공약·기루다·결과·판 점수, 최대 500판)로 함께 저장한다. 게임별 통계 나의 기록은 판 내역이 있는 마이티 기록이면 판당 평균 점수(요약 줄에 누적)·주공 성공률·프렌드 승률·야당 방어율, 최근 경기 3개(누르면 기록 열기), 포지션별 성적, 프렌드 궁합(최대 5줄), 통계 집계 기준을 보여 준다.

### 4.6 승패 기록의 개인전·팀전

- `승패 기록`을 선택하면 `개인전`과 `팀전`을 먼저 선택한다.
- 개인전은 기존 플레이어별 승패 입력 UI를 사용한다.
- 팀전은 플레이어가 2명 이상일 때 선택할 수 있고 2~4팀을 지원한다. 팀 수는 플레이어 수를 넘을 수 없다.
- 팀전 최초 진입 시 플레이어 추가 순서대로 각 팀에 번갈아 자동 배정한다.
- 팀 구성 화면에서 팀 이름을 수정하고 플레이어를 눌러 다음 팀으로 이동할 수 있다.
- 개인전과 팀전 결과 CTA는 짧게 `승`, `무`, `패`로 표시한다.
- 개인전은 한 플레이어의 결과를 선택하면 전체 결과를 다시 계산한다. 선택자가 승이면 나머지는 패, 선택자가 패면 나머지는 승, 무승부면 모두 무승부로 입력한다.
- 팀전 결과 화면에서는 팀 단위로 승리·무승부·패배를 선택한다. 한 팀 승리 선택 시 나머지 팀은 패배, 무승부 선택 시 모든 팀은 무승부가 된다.
- 팀전 결과 카드의 첫 줄에는 팀명과 `승`·`무`·`패` CTA를 양쪽에 배치한다. 팀별 카드는 포함된 첫 플레이어의 랜덤 색상을 사용한다. 참가자는 `닉네임 ×` 칩으로 표시하며 닉네임은 수정, `×`는 확인창 없이 해당 참가자를 삭제한다.
- 팀전 참가자 칩을 길게 누르면 확대·떠오름·대비 테두리로 드래그 선택 상태를 표시한다. 진동을 지원하는 기기에서는 선택 순간 짧게 한 번 진동한다. 첫 터치의 사용자 활성화가 아직 없거나 호출이 거절된 경우, 드래그 종료 터치에서 한 번만 재시도한다. 진동 미지원·차단 시에도 시각 효과와 이동은 유지한다. 다른 팀 카드 위에서 놓으면 해당 팀으로 이동한다. 빈 팀이 생기지 않도록 팀의 마지막 참가자는 이동하지 않는다.
- 팀전 결과 카드를 왼쪽으로 스와이프하면 해당 팀과 참가자를 확인창 없이 삭제한다. 팀전은 최소 2팀을 유지하므로 2팀만 남은 상태에서는 팀 삭제를 실행하지 않는다.
- 참가자 칩에서 시작한 제스처는 팀 카드 스와이프 삭제를 실행하지 않는다. 드래그가 취소되거나 팀 밖에 놓이면 소속을 유지한다. 팀 이동 후에는 소속이 바뀐 두 팀의 결과를, 팀 삭제 후에는 남은 모든 팀의 결과를 다시 선택한다. 삭제한 참가자는 다른 기록 방식으로 전환해도 복원되지 않는다.

| 팀전 결과 상태 | 제스처/CTA | 실행 액션 |
| --- | --- | --- |
| 참가자가 2명 이상인 팀 | 참가자 칩 길게 누른 뒤 다른 팀에 놓기 | 소속 이동, 결과 초기화, 진행 중 기록 저장 |
| 참가자가 1명인 팀 | 마지막 참가자를 다른 팀에 놓기 | 이동하지 않고 최소 인원 안내 |
| 3~4팀 | 카드 빈 영역·제목 영역에서 왼쪽 스와이프 | 팀과 소속 참가자 삭제, 결과 초기화, 진행 중 기록 저장 |
| 2팀 | 팀 카드 왼쪽 스와이프 | 삭제하지 않고 최소 2팀 안내 |
| 모든 팀 | 닉네임 짧게 누르기 / × | 기존 이름 수정 / 참가자 삭제 |
- 팀전 결과 화면에서 플레이어 추가 시 소속 팀을 선택하며, 플레이어 수정창에서도 팀을 변경할 수 있다.
- 팀 정보는 플레이어의 `teamId`, `teamName`으로 기록에 보존하여 개인 통계와 팀 기록을 구분할 수 있게 한다.

### 4.7 역할전

스파이폴·마피아·아발론·머더미스터리처럼 숨은 역할 쪽과 나머지 쪽이 겨루는 게임을 빠르게 기록한다.

- `승패 기록` 다음 선택을 `개인전 · 팀전 · 역할전` 3개로 늘린다. 역할전은 플레이어가 2명 이상일 때 선택할 수 있다.
- 역할전은 항상 2진영이다. 진영 이름 기본값은 게임에 따라 정하고 결과 화면에서 고칠 수 있다.

| 게임 | 숨은 역할 진영 | 나머지 진영 |
| --- | --- | --- |
| 이름에 스파이폴·Spyfall 포함 | 스파이 | 시민 |
| 이름에 아발론·Avalon·레지스탕스·Resistance 포함 | 악 | 선 |
| 그 밖(마피아·늑대인간·시계탑 등 포함) | 마피아 | 시민 |

- 결과 화면은 플레이어 목록 하나, `누가 이겼나요?` 아래 진영 색의 승리 CTA 두 개(`{숨은 역할} 승` · `{나머지} 승`, 선택 시 ✓), 작은 `진영 이름 바꾸기`로 구성한다.
- 플레이어를 누르면 숨은 역할 진영으로 지정·해제한다(빨간 표시). 지정하지 않은 플레이어는 모두 나머지 진영이다. 길게 누르면 플레이어 수정창(이름 수정·삭제)을 연다.
- SAVE 활성 조건: 숨은 역할 진영 1명 이상, 나머지 진영 1명 이상, 이긴 진영 선택.
- 역할 지정을 바꾸면 이긴 진영 선택을 지운다.

| 역할전 상태 | CTA | 실행 액션 |
| --- | --- | --- |
| 진입 직후 | 플레이어 누르기 | 숨은 역할 진영 지정 |
| 양쪽 진영 1명 이상 | `{진영} 승` | 해당 진영 승리, 다른 진영 패배 |
| 한쪽 진영 0명 | `{진영} 승` 비활성 | 안내: 양쪽 진영에 1명 이상 필요 |
| `진영 이름 바꾸기` → 진영 이름 칸 | 이름 수정(비우거나 다른 진영과 같으면 되돌림) | 해당 진영 플레이어의 팀 이름도 바꿈. 평소에는 이름 칸을 숨김 |

저장 형식: 새 필드 없이 기존 팀전 형식으로 저장한다(`teamId` `team-1` = 숨은 역할 진영, `team-2` = 나머지 진영, `teamName` = 진영 이름, 플레이어별 `winner`). 통계에서는 팀전 기록으로 집계되고, 기록 수정 화면도 팀전과 같다. 역할전으로 입력했다는 표시는 남기지 않는다.

### 4.8 연속 판

같은 게임을 같은 사람들과 여러 판 할 때 판마다 처음부터 입력하지 않게 한다.

- 대상: 점수 없는 결과 기록 중 개인전·팀전·역할전·순위. 점수 기록과 협력 기록은 이번 범위에서 제외한다.
- 저장창 2단계(날짜·장소)에서 `저장하기` 위 한 줄에 `저장하고 다음 판`을 둔다. 두 CTA는 같은 저장 액션을 부르고 다음 판 여부만 다르다.
- `저장하고 다음 판`: 이번 판을 저장한 뒤 게임·날짜·장소·참가자·진영 이름·팀 구성은 그대로 두고 결과(승패·순위·역할 지정)만 지운 결과 화면으로 돌아간다. 저장 알림은 `{n}판째 저장했습니다.`로 표시한다.
- 결과 화면 제목 옆에 `{n}판째`를 표시한다(묶음의 저장된 판 수 + 1).
- 다음 판의 SAVE는 저장창 2단계부터 연다(게임이 정해진 상태, 3.0과 같음).
- `저장하기`를 누르면 그 판까지 같은 묶음으로 저장하고 묶음을 끝낸다. `기록 취소`·리셋·기록 방식 변경은 저장 없이 묶음을 끝낸다. 다음 저장은 새 묶음이다.
- 새로고침하면 진행 중인 묶음 번호와 판 수를 결과 초안에서 복원한다.

저장 형식: 판마다 지금처럼 기록 하나를 저장하고, 같은 묶음의 기록에 선택 필드 `sessionId`(묶음 첫 판에서 만든 UUID)를 넣는다. 승률·통계는 지금처럼 판 단위로 센다. `sessionId`는 클라우드 동기화에는 포함하고 BGG 내보내기에는 보내지 않는다. 기존 기록은 바뀌지 않는다.

기록 목록 묶음 표시(같은 `sessionId`를 `스파이폴 ×5판 · 길동 3승` 한 카드로 접기)는 다음 단계로 미룬다.

## 5. 게임 기록 저장 CTA

### 4.9 스토리·추리

콰이어트벨·시장 남상근의 죽음처럼 이야기를 따라가 결말을 보거나 각자 범인을 추리하는 게임을 기록한다. 한 시나리오를 보통 한 번만 하므로 통산 판 수·연승·점수 대신 결말과 추리 결과를 남긴다.

- 진입: 결과 방식 선택에 `추리 기록`을 추가한다(`승패 기록` 아래). `협력 기록` 다음 선택에 `스토리 결말`을 추가한다(협력 방식 다섯 번째).
- 추천: 게임 이름에 머더·미스터리·살인·죽음·탐정·추리·사건·Murder·Mystery·Detective가 들어가면 `추리 기록`에 추천 표시.

#### 스토리 결말 (협력 방식의 하나)

- 결과 화면: 참가자 목록, `결말을 봤나요?` 아래 `성공 결말` · `실패 결말` CTA(하나 선택, ✓), `결말 이름`(선택, 40자 이내, 예: 진엔딩·배드엔딩 2). 결말 이름 칸 아래에 이 게임에서 전에 쓴 결말 이름을 칩으로 제안(누르면 채움).
- SAVE 활성 조건: 성공·실패 중 하나 선택.
- 저장: `rule: cooperative`, `cooperativeResult`, 결말 이름이 있으면 `ending`(문자열). Firestore 규칙에 `ending` 허용 추가 필요(배포 전에는 결말 이름이 있는 기록의 클라우드 저장이 거절됨).

| 스토리 결말 상태 | CTA | 실행 액션 |
| --- | --- | --- |
| 진입 직후 | `성공 결말` / `실패 결말` | 결과 선택(다시 누르면 다른 쪽으로 바뀜), SAVE 활성 |
| 결말 이름 칸 | 입력 / 제안 칩 | 결말 이름 저장(앞뒤 공백 제거, 비우면 저장하지 않음) |

#### 추리 기록

- 결과 화면: 플레이어 목록 하나. 줄마다 왼쪽 `범인` 표시(누르면 지정·해제, 빨간 표시)와 오른쪽 추리 결과 분할 버튼 `맞힘 · 틀림 · 기권`(범인 줄은 숨김). 아래 `사건 결과` 아래 `범인 검거` · `범인 도주` CTA(하나 선택, ✓). 줄을 길게 누르면 플레이어 수정창(이름 수정·삭제·맡은 캐릭터 입력).
- 승자는 자동: `범인 검거`면 추리를 맞힌 사람 모두 우승(범인·틀림·기권은 패배), `범인 도주`면 범인 우승(나머지 패배).
- SAVE 활성 조건: 범인 1명 이상, 범인 아닌 사람 1명 이상, 범인 아닌 사람 모두 추리 결과 선택, 사건 결과 선택.
- 범인 지정을 바꾸면 그 사람의 추리 결과를 지운다.

| 추리 기록 상태 | CTA | 실행 액션 |
| --- | --- | --- |
| 진입 직후 | 줄의 `범인` | 범인 지정(추리 칸 숨김) |
| 범인 아닌 줄 | `맞힘` / `틀림` / `기권` | 그 사람의 추리 결과 |
| 범인 0명 또는 모두 범인 | `범인 검거`·`범인 도주` 비활성 | 안내: 범인과 추리한 사람이 1명 이상 필요 |
| 조건 충족 | `범인 검거` / `범인 도주` | 사건 결과, 승자 자동 계산, SAVE 활성 |

저장 형식: 플레이 필드는 새로 만들지 않는다(`rule: highest`, 점수 null). 플레이어별 `winner`(자동 계산) + `culprit: true`(범인) + `guess: right|wrong|pass`(범인 아닌 사람) + 맡은 캐릭터가 있으면 `character`(40자 이내). 플레이어 항목은 Firestore 규칙이 키를 제한하지 않아 규칙 변경 없이 클라우드에 저장된다. 기록 방식 이름은 `추리`.

#### 통계 (게임별 통계에서 그 게임이 추리·스토리 결말 방식일 때)

- 추리: 나의 추리 정답률(맞힘 / 추리한 판), 범인이었을 때 도주 성공, 맡았던 캐릭터, 함께 맞힌 사람.
- 스토리 결말: 완주한 판, 결말 수집(성공·실패 결말 이름 목록, 같은 이름은 한 번).
- 이 방식에는 통산 판 수 기반 연승·최고점·점수 차 이야기를 넣지 않는다.

#### 공유 이미지 (스포일러 방지 기본)

- 표지 요약: 추리는 `사건 해결 · 추리 성공 3/5명` 또는 `범인 도주`, 스토리 결말은 `성공 결말` / `실패 결말`.
- 범인 이름·캐릭터·결말 이름은 기본으로 넣지 않는다. 공유 창에 `결말 공개` 스위치(친구 공유용일 때만, 기본 끔)를 켜면 결말 이름과 범인을 넣는다.
- 우승자 표시: 추리를 맞힌 사람(검거) 또는 범인(도주)을 우승자로 표시한다.

### 5.1 점수 게임 저장

```text
SAVE
→ 게임 종료 다이얼로그
→ 점수 저장
→ 1단계: 게임 검색·최근 게임·BGG 게임 ID에서 게임 선택
→ (BGG 확장이 있는 본판이면) 1단계 안에서 함께 사용한 확장 선택 → 다음
→ 2단계: 선택한 게임·날짜·장소·승리 조건 확인
→ 기록 저장
→ 성공 안내
```

게임 검색 결과나 최근 게임을 선택하면 즉시 2단계로 이동한다. 단, BGG 게임 정보에 확장이 있는 본판을 고르면 1단계에 확장 선택을 열고 `다음`으로 2단계에 간다. 검색 결과에서 확장을 고르면 그 확장의 본판을 선택하고 고른 확장을 미리 선택한다. 확장 정보는 BGG 게임 정보로 확인하며, 받을 수 없으면(비로그인·오류) 지금처럼 바로 2단계로 간다. 직접 입력한 게임명과 BGG 게임 ID는 `다음`으로 2단계에 확정한다. 2단계의 `게임 다시 선택`은 입력한 날짜·장소·승리 조건을 유지한 채 1단계로 돌아간다.

`초기 화면으로 돌아가기`는 현재 점수판만 비우며 이미 저장된 기록을 삭제하지 않는다.

### 5.1.1 게임 검색 상황별 표시

게임 검색은 세 곳에서 같은 검색(기본 목록·내 기록·별칭·BGG 전체 검색, 같은 BGG 오류 안내)을 쓰고, 상황별 차이는 이 표 하나로 정한다(`game-search.js`의 `GAME_SEARCH_CONTEXTS`).

| 항목 | 점수판 SAVE | 결과 기록 SAVE(점수 없이) | 게임 탭 게임 추가 |
| --- | --- | --- | --- |
| 제목 | 게임 검색 | 게임 검색 | 게임 추가 |
| 최근 게임 | 접힌 채 표시 | 펼친 채 표시 | 없음 |
| 확장 선택 | 있음 | 있음 | 없음(목록에는 본판만) |
| 고른 뒤 | 확장 선택 → 2단계 | 확장 선택 → 2단계 | 선택 표시·입력칸 채움 |
| 마지막 CTA | 다음 → 저장하기 | 다음 → 저장하기 | 등록 |
| 화면 | 1단계는 전체 화면, 제목 없이 검색칸 왼쪽 `←`(취소와 같음). 확장 선택·2단계 제목 `선택된 게임`, 닫기 × 없음 | 같음 | 전체 화면, 제목 없이 `←` |

| 한글 이름 기억 | 저장할 때 | 저장할 때 | 등록할 때 |

### 5.2 저장 공통 검증

두 저장 모달의 표시 및 CTA는 다음 상태표를 따른다. 초기 `게임 기록하기` 설정 흐름에는 적용하지 않는다.

| 상태 | 입력 및 표시 항목 | 노출 CTA | 실행 액션 |
| --- | --- | --- | --- |
| 모든 기록 방식 → `경기 기록 저장` 1단계(전체 화면, 제목 없음) | `←`·게임 검색·최근 게임·BGG 게임 ID | 다음 · 취소(`←`도 취소) | 검색 결과나 최근 게임 선택 시 즉시 2단계 이동, 직접 입력은 `다음`으로 확정 |
| 모든 기록 방식 → 1단계 · 확장 있는 본판 선택 | 선택한 본판(`다시 검색`), `함께 사용한 확장 (선택)`과 선택 수, 확장 칩(보유 → 위시·하고 싶은 → 직전 선택, 나머지는 `다른 확장 검색`), BGG 게임 ID·Powered by BGG | 다음 · 취소 | 다음은 선택한 확장을 유지한 채 2단계 이동, 선택 없이 다음이면 본판만 기록, `다시 검색`은 검색 결과로 복귀 |
| 모든 기록 방식 → `경기 기록 저장` 2단계 | 1단계를 거쳐 오면 전체 화면 제목 `선택된 게임`(× 없음), 게임이 이미 정해져 2단계부터 열면 창 제목 `저장하기`와 ×. 선택된 게임, 날짜·장소(새 장소는 직접 입력, 추천 목록은 이 계정 기록에 쓴 장소를 자주 쓴 순·같으면 최근 순으로 최대 30개, 그 뒤에 집·보드게임 카페·모임 장소·온라인 중 아직 안 쓴 것), 점수 기록일 때만 승리 조건 | 게임 다시 선택 · 저장하기 | 현재 점수판 또는 입력한 승패·팀·순위·협력 결과를 게임 정보와 함께 저장 |
| 로그인 여부 변경 | 두 저장 모달의 동일한 표시 규칙 | 이 기기에 저장 | 기존 계정별 저장 및 수동 동기화 대기 처리 유지 |

- 두 저장 모달에서 `점수 없이 기록` 옵션과 참여자·점수·승리 미리보기를 표시하지 않는다.
- 모든 기록 방식은 같은 `경기 기록 저장` 컴포넌트와 2단계 전환을 사용한다. 승패·팀·순위·협력 기록에는 승리 조건을 표시하지 않는다.
- 1단계에는 기록 정보 입력을, 2단계에는 검색 UI를 표시하지 않는다.
- 확장 칩은 누를 때마다 선택·해제한다. 같은 게임의 직전 기록에 쓴 확장을 미리 선택한다. 2단계의 선택한 게임 아래에 `+ 확장명`(2개 이상은 `+ 확장 N`) 배지를 표시한다.
- 1단계 하단의 `BGG 게임 ID 입력 수동으로 추가 (선택)`과 Powered by BGG는 확장 선택 중에도 유지한다.
- BGG 로고·게임 ID 입력·웹 검색을 표시하되 자체 게임 선택 시 웹 검색만 숨긴다.
- 두 저장 모달에서 `로그인해서 저장`과 저장 위치 안내는 숨긴다.
- 취소·닫기는 현재 입력 화면과 기존 저장 기록을 유지한다.

- 게임명과 날짜가 유효해야 한다.
- 저장 대상 플레이어가 1명 이상이어야 한다.
- 계정 전환 중이거나 저장 컨텍스트가 달라졌으면 저장을 중단한다.
- 로컬 저장 실패 시 화면 상태와 기존 기록을 원래대로 되돌린다.
- 로그인 상태에서도 기록 저장·수정·삭제는 먼저 로컬에만 반영하고 클라우드 대기열에 둔다.
- 로그인 직후나 네트워크 재연결만으로 클라우드 동기화를 시작하지 않는다.
- 클라우드 읽기·쓰기는 사용자가 설정의 `클라우드 동기화`를 누른 뒤에만 실행한다. BGG 사용자명·컬렉션·플레이 기록의 클라우드 받기도 이때 함께 한다(로그인만으로 받지 않음).
- BGG에서 받기(`내 정보 가져오기`)와 BGG로 보내기(`기록 내보내기`)는 해당 버튼을 누른 경우에만 실행한다. 자동 새 정보 확인은 하지 않는다.
- 로그인 중 받은 클라우드·BGG 데이터는 로그아웃해도 이 기기에 남고, 같은 ID의 데이터는 덮어쓴다.
- `내 정보 가져오기`로 받은 BGG 플레이 중 Score Counter가 내보낸 경기(메모의 `[ScoreCounter:기록ID]`)가 이 기기에 없으면 그 ID로 Score 기록을 되살린다(다른 기기에서 내보낸 기록을 클라우드 동기화 없이 받기 위한 보조 수단). 이미 있는 기록은 덮어쓰지 않고, 이 기기에서 삭제했거나 클라우드 동기화로 삭제를 받은 기록은 되살리지 않는다. 복원은 BGG 형식에 있는 정보(게임·날짜·장소·플레이어 이름·색·점수·승패·나 지정, 높은/낮은 점수 승리)만 쓰고, 협력 경기는 결과 미입력 협력 기록으로 되살린다(협력 결과·시나리오·난이도·미션·팀·순위·공동 점수·시나리오 레벨·확장은 없음). 되살린 기록은 다음 클라우드 동기화에서 클라우드에 원본이 있으면 원본으로 바뀌고, 없으면 클라우드에 올린다.
- 비로그인 상태에서도 기기 저장은 가능해야 한다.

- Score Counter 자체 게임은 BGG 검색 및 연동 대상에서 제외한다. 게임 검색(경기 기록 저장 1단계, 게임 탭 게임 추가)은 검색어가 자체 게임 이름·별칭과 정확히 같을 때만 BGG 검색을 건너뛴다.
- 게임 검색(경기 기록 저장 1단계, 게임 탭 게임 추가)은 로그인하지 않아도 기본 목록과 BGG 전체 검색을 쓴다. BGG 게임 정보(한글 이름·표지·확장판)도 로그인하지 않아도 받는다(같은 접속 주소별 제한). 비로그인 BGG 검색은 이 앱 사이트에서 온 요청만, 접속 주소별 2분 30회로 제한한다. BGG 컬렉션·플레이 가져오기와 BGG 연결 기능은 계속 로그인이 필요하다.
- BGG에서 가져온 게임명은 `&amp;` 같은 표기를 실제 문자로 바꿔 저장·표시한다. BGG 게임 정보에 한글 이름이 있으면(없으면 앱 내장 한글 게임 목록의 이름) 게임 탭과 게임별 통계에서 한글로 표시하고(이미 가져온 게임 포함), 검색은 한글·원래 이름 모두로 된다.
- BGG 컬렉션 게임은 BGG ID로 내 게임 목록·기록과 매칭해 한 줄로 합치고 플레이 횟수를 그대로 보여 준다. 게임 탭은 BGG 컬렉션을 읽기만 하며 내 게임 목록 저장값은 바꾸지 않는다(컬렉션 변경은 게임별 통계의 컬렉션 관리 메뉴에서만, BGG 반영은 기록 내보내기 때).
- BGG 컬렉션을 가져오지 않았으면 하고 싶은·보유·위시 리스트·펀딩 탭은 `{보유 게임 등}을 등록하거나 BGG 컬렉션을 설정에서 불러올 수 있어요.`를 보여 준다. 해본 탭이 비어 있으면 `아직 플레이한 게임이 없습니다. 기록을 저장하거나 게임을 추가하세요.` 보유 게임이 하나도 없으면(검색 결과 없음 제외) 보유 탭은 빈 문구를 흐린 예시 책장(원목 선반 2줄, 표지 없는 상자 실루엣, 누를 수 없음) 위에 보여 준다.
- 보유 탭은 줄 목록 대신 `내 컬렉션 책장`으로 그린다. 원목 선반 책장(벽은 앱 어두운 배경 그대로, 선반만 실제 원목 assets/wood-plank.jpg(ambientCG Wood092, CC0)로 원근 윗면·두께 있는 앞면·벽 그림자, 표지는 한 줄 3개가 폭을 거의 채우게 크게, 선반 양옆 여백, 우측 색인은 오른쪽 여백)에 첫 글자 묶음(목록 색인과 같은 0~9 · ㄱ~ㅎ · A~Z · #)마다 책장 한 칸, 칸 안에 표지를 한 줄 3개(화면 폭 640px 이상은 5개)씩 놓고 줄마다 위에서 비추는 빛과 원목 선반(밝은 윗면·나뭇결·아래 그림자)을 그린다. 글자는 그 칸 첫 선반 앞면에 새긴 듯 작고 옅게. 표지는 모두 같은 정사각 상자이고, 그림은 빈 여백 없이 상자 비율 그대로 보이되 같은 정사각 틀 안에 들어가게 가로가 길면 폭에, 세로가 길면 높이에 맞춰 선반 위에 세운다(앞·뒷면 사진은 COVER_CROPS의 앞면 구간과 세로 기준). 표지가 없거나 못 불러오면 게임 이름을 쓴 표지 카드. 표지를 누르면 목록 줄과 같이 게임별 통계로 간다. 검색어·우측 색인(누르면 그 글자 칸으로 이동)·개수는 그대로. 책장에는 밀어서 삭제가 없다(보유 게임은 BGG 컬렉션에서 정리).
- 게임 줄의 보조 문구는 `플레이 N회 · BGG 플레이 M회`이다. BGG 횟수는 BGG 컬렉션의 플레이 수와 가져온 BGG 플레이 기록 중 큰 값이다.
- 표지는 BGG 컬렉션 표지를 먼저 쓰고, 없으면 로그인 상태에서 BGG 게임 정보로 보충한다.
- BGG 대표 이미지가 상자 앞·뒷면을 나란히 찍은 사진인 게임(game-artwork.js COVER_CROPS, 예: 차가운 그녀가 눈을 뜨기 전에)은 목록·책장·공유 이미지 모두 앞면 구간만 보인다.
- 검색 중 계정 또는 화면 컨텍스트가 변경되면 결과 적용을 중단한다.

- 팀전·개인 승패·순위·협력·점수 통계를 분리한다. 전체 플레이 횟수는 경기당 한 번 센다.
- 팀전은 같은 팀원을 상대 전적에서 제외하며, A팀 같은 임시 팀 이름을 경기 간 같은 팀으로 합산하지 않는다.
- 게임별 통계의 나의 기록에서 그 게임의 팀전 기록이 모두 이름 있는 2진영(역할전 등, 기본 팀 이름 A~D팀 제외)이면 첫 요약을 `플레이 · 전체 승률 · {진영} 승률 {n}회`로 보여 준다(많이 맡은 진영 2개). 팀 승리·팀전 승률·무승부, 결과 확인·미입력 문구, 별도 진영 섹션, `통계 집계 기준`은 표시하지 않는다.
- 순위의 평균은 참가 인원별로 구분하고 공동 1위도 1위 비율에 포함한다.
- 협력 성공률은 성공·실패가 명시된 경기만 분모로 사용한다. 기존 협력 기록의 개인 승자 정보로 전체 결과를 추정하지 않는다.
- 기존 기록은 변환하거나 덮어쓰지 않는다. 새 협력 기록에만 선택적인 `cooperativeResult`와 `sharedScore`를 추가한다. 초안은 해당 값을 복원하며 계정별 저장 경계를 유지한다.
- 기록에 방식이나 결과를 판별할 정보가 부족하면 결과 미입력으로 표시한다.
- 사용한 확장은 기록의 선택 필드 `expansions: [{id, name}]`(BGG 확장 ID, 1~30개)로 저장한다. 확장이 없는 기존 기록은 그대로 둔다.

- 기간 분석의 `플레이 달력`: 선택 기간이 62일 이하면 요일 7칸 달력(날짜와 판 수, 많이 한 날일수록 진한 색), 366일 이하면 달마다 한 줄 1~31일 칸, 그보다 길거나 전체 기간이면 기존 월별 `플레이 빈도` 막대. 아래에 가장 많이 한 날(M/D · N판)과 가장 길게 이어 간 연속 플레이 날(2일 이상일 때). `플레이 장소`는 장소를 적은 기록이 있을 때만 장소별 판 수(5곳까지)와 막대를 보여 준다.
- 기간 분석은 기간 요약·플레이 빈도 아래에 선택 기간 기준의 `방식별 나의 성적`, `어떤 게임을 했을까`(가족/파티(추상·테마 포함)·추리·협동·방탈출·전략·스포츠·미분류 묶음별 서로 다른 게임 수, 게임당 한 묶음), `많이 플레이한 게임`(상위 8개)을 표시한다. 모든 카드 사이 간격은 같다(14px). `방식별 나의 성적`은 방식마다 판 수, 큰 승률(협력은 성공률·순위는 1위 비율), 승률 막대와 경기 인원(팀전은 팀 수)으로 본 기대 승률 세로선, 승리·무승부(협력은 성공·실패) 횟수, 기대 대비 차이 칩(높으면 초록·낮으면 빨강)을 보여 주고, 결과가 5판 이상인 방식 중 기대보다 가장 잘한 방식을 맨 위에 안내한다(판 수 많은 순).
- 기간 분석과 게임별 통계(게임 선택 목록의 횟수 포함)는 내가 플레이어로 참여한 기록(내 플레이어 지정 또는 내 닉네임 일치)만 집계한다. 내가 없는 기록은 저장·기록 목록에 그대로 남지만 통계에서는 플레이하지 않은 것으로 본다. 최근 기록은 전체 기록 기준이다.
- 게임별 통계 · 나의 기록은 기록 방식 선택 없이 그 게임에서 가장 많이 쓴 방식으로 보여 준다. 점수·결과를 적지 않은 판도 플레이 횟수에 넣고 승률에서는 뺀다(일부 사람만 점수를 적은 판은 적힌 점수만 평균·최고점에 넣는다).
- 게임별 통계와 기간 분석(기간 요약 바로 아래)은 `상대 전적` 카드를 표시한다: 그 기록에서 만난 이름 있는 상대를 함께한 판수 순으로 모두(8명까지, 나머지는 더 보기) 보여 주고 줄마다 함께한 판수·최근 날짜·승패무·승률을 쓴다. 승패는 나와 그 상대의 순위(없으면 승리 조건에 따른 점수, 승패 기록 방식은 승패)를 비교하며 비교할 수 없는 경기는 승률에서 뺀다. 3판 이상 비교한 상대 중 가장 많이 이긴·진 상대를 위에 강조한다. 협동 경기와 익명 상대는 제외한다. 같은 사람은 이긴 수가 진 수보다 많을 때만 '가장 많이 이긴 상대', 진 수가 더 많을 때만 '나를 가장 많이 이긴 상대'로 강조한다. 다인 경기는 나와 그 상대 중 앞선 사람을 승으로 센다. 경쟁 상대가 없고 협동 기록만 있으면 같은 카드에 `함께한 사람`(함께한 판수·성공 횟수·성공률)을 보여 준다. 기간 분석 카드는 숫자가 선택 기간 기준이며 줄을 누르면 전체 기간 전적이 열린다고 안내한다.
- `○○와의 전적` 화면(통계 탭 안): 전체 기간 기록으로 함께한 판수·내 승리·상대 승리·무승부와 비율 막대, 최근 5판 흐름(연승·연패), 게임별 전적(3판 이상이면 내가 우세·상대 우세·팽팽, 미만은 기록 적음), 함께한 협력 게임(같이 참여한 협동 경기의 성공률), 최근 대결 3개를 보여 준다. 기록의 플레이어 이름은 편집을 열므로 진입점으로 쓰지 않는다. 머리에 '전체 기간'을 표시한다. 연승·연패는 범위 안 전체 기록에서 세고 점은 최근 5판만 보인다. 최근 대결의 점수·순위가 없으면 승리·패배·무승부로 쓴다. 다인 경기가 있으면 앞선 순위를 승으로 셌다고 안내한다. 전체 게임 범위에서 2판 이상 비교한 게임이 2개 이상이면 `다음에 같이 해볼 게임`(팽팽한 승부·지난 맞대결·자신 있는 게임, 서로 다른 게임 최대 3개)을 보여 준다. 경쟁 기록 없이 협동 기록만 있으면 협력 카드만 보여 준다.

### 데이터 가져오기 · BG Stats

- BG Stats 파일의 게임명·날짜·장소(locations의 이름)·플레이어·점수·승자를 가져온다. 메모·사진·컬렉션·도전과제는 가져오지 않는다.
- 같은 기록(같은 ID)은 중복으로 건너뛰되, 기존 기록에 장소가 없고 파일에 있으면 장소만 채운다(미리보기에 `장소 채움 N개`, 새 기록이 없어도 가져오기 가능).
- BG Stats 파일의 플레이별 BGG 플레이 번호(bggId)를 기록의 `bggPlayId`로 저장하고(다시 가져오면 기존 기록에도 채움), 이 번호의 BGG 플레이를 같은 경기로 본다. 번호가 없는 기록만 게임 BGG ID·날짜·참가자 이름·점수가 모두 같은 BGG 플레이(#bgstats)와 같은 경기로 본다. 이 기록은 BGG 내보내기에서 제외(`BG Stats가 이미 BGG에 올림 N개`)하고, 장소 관리 횟수도 한 번만 센다. BG Stats가 BGG에 줄여 올린 장소(`B.`)는 기록의 원래 장소로 대신한다.

- BG Stats 기록 중 이 앱이 올린 플레이가 없는 것은 BGG 내보내기 때 BG Stats 원본(bggPlayId)을 Score 기록 내용(원래 장소 포함)으로 업데이트하고 이후 그 원본을 업데이트 대상으로 쓴다. 그 날짜의 내 BGG 플레이에 원본이 없으면(지워진 경우) 새 플레이로 올린다.
- BGG로 기록 내보내기 때, BG Stats 원본이 지금 BGG에 있는데 Score가 따로 올린 플레이(업로드 기록이 있는 것)는 확인창에 개수를 알리고 BGG에서 삭제한 뒤 내보낸다. 원본이 BGG에 없으면(이미 삭제) Score가 올린 플레이를 남기고 평소처럼 업데이트한다. 워커는 이 앱이 올린 플레이 번호만 삭제한다.
- BGG에서 지워진 플레이: 마지막 전체 플레이 가져오기(playsFullAt)가 그 기록을 보낸 뒤인데 가져온 BGG 플레이에 보낸 번호가 없으면 '변경 없음'으로 빼지 않고 내보내기 대상에 넣는다. 워커가 그 날짜의 BGG 플레이에서 번호를 다시 확인해 정말 없을 때만 새 플레이로 올리고, 있으면 '이미 등록된 동일 기록'로 센다.
- 다른 기록 ID로 올라간 같은 경기: BGG에 보낸 번호가 없는 기록은 같은 게임 BGG ID·날짜·참가자 이름·점수의 BGG 플레이 중 다른 기록과 연결되지 않은 것(Score 표시가 있으면 그 기록 ID가 이 기기에 없는 것)을 하나씩 짝지어 새로 올리지 않고 그 플레이를 업데이트한다.
- 전송 결과가 불확실한 기록(확인 필요)은 다음 내보내기에서 워커가 Score 표시로 BGG를 찾고, 못 찾아도 불확실해진 지 1시간이 안 됐으면 다시 올리지 않고 '확인 필요'로 둔다(BGG 조회 반영 지연으로 인한 중복 방지).

| 숨기기 · 보이기 | 추천 목록에서 빼거나 되돌린다 | 기록은 바꾸지 않는다. 숨긴 장소는 목록 아래에 흐리게 표시 |
| 이름 바꾸기 | 새 이름 입력 후 바꾸기 → 확인창(기록 수·되돌릴 수 없음, 이미 있는 이름이면 합치기 안내) | 이 계정 기록의 장소를 모두 새 이름으로 바꾸고 로그인 중이면 클라우드 저장 대기에 올린다. BGG에만 있는 장소·이미 내보낸 BGG 플레이는 바뀌지 않는다(기록이 없는 장소는 버튼 없음) |

- 기본·숨김 설정은 계정별로 이 기기에 저장한다(비로그인은 게스트). 클라우드 동기화하지 않는다.
- 기간 분석 `플레이 장소`는 장소별 방문 횟수다: 같은 날 같은 장소는 몇 판을 했어도 1회(`N회`).
- BGG 플레이 장소는 `내 정보 가져오기`로 받은 플레이의 location 값을 쓴다.

- 플레이어·장소 이름처럼 사용자가 입력한 값은 번역하지 않는다. 언어 선택지의 `한국어`·`English`는 항상 그 언어 이름으로 표시한다.

## 9. 구현 불일치 추적

아래 항목은 이 문서 기준과 현재 구현이 다를 수 있으므로 관련 작업 시 우선 확인한다.

| 항목 | 기준 | 확인할 현재 구현 |
| --- | --- | --- |
| 메인 플레이어가 있는 점수 없는 기록 | 현재 플레이어 사용, 인원 선택 생략 | 인원을 2명으로 초기화하고 다시 선택하는지 확인 |
| 점수 없는 결과의 SAVE | 게임 정보 입력 액션 직접 호출 | 숨겨진 저장 버튼 `.click()` 위임 제거 |
| 빈 점수판 우측 상단 추가 | 랜덤 플레이어 한 명 즉시 추가 | 이름·색상 입력 화면이 열리지 않는지 확인 |
| 개인전·순위·협력 결과 입력 중 플레이어 추가 | 랜덤 플레이어 한 명 즉시 추가 | 이름·색상 입력 화면이 열리지 않는지 확인 |
| 팀전 결과 입력 중 플레이어 추가 | 이름·색상·소속 팀 입력 | 소속 팀 선택 화면이 유지되는지 확인 |

2026-10-20 동기화 점검에서 재현한 별도 개선 대상 (아직 미수정):

- `기기 기록 복구` 확인 콜백이 `sync()`를 직접 호출해 즉시 업로드한다. 동기화 CTA에서만 업로드한다는 정책과 불일치한다.
- 클라우드 읽기 중 `recordRevision`이 바뀌면 받은 서버 목록을 반영하지 않고 로컬 업로드만 수행한 뒤 `동기화됨`으로 표시한다.

### 새로고침 시 화면 복원

| 상태 | 초기 표시 | 복원 완료 |
| --- | --- | --- |
| 홈에서 점수/승패/팀전/순위/협력 기록 중 새로고침 | 중립적인 불러오기 상태 | 계정 확인과 해당 기록방식 복원을 마친 화면만 표시 |
| 게임·통계·설정에서 새로고침 | 요청한 탭 선택 상태와 불러오기 표시 | 같은 탭 유지, 홈의 진행 중 기록은 백그라운드 복원 |
| 모듈/계정 확인 지연 | 12초 뒤 다시 불러오기 CTA 제공 | 복원이 늦게 완료돼도 정상 화면으로 전환, 기록을 지우지 않음 |

- 기록 모듈은 모든 진입점에서 같은 URL로 가져와 한 번만 초기화한다.
- 복원 동작은 홈으로 강제 이동하거나 다른 탭 위에 작성 다이얼로그를 열지 않는다. 사용자가 새 기록을 시작하는 액션은 기존대로 홈으로 이동한다.
- 로그인·자동 동기화 정책과 저장 기록 형식은 변경하지 않는다.

## 10. 변경 요청 작성 형식

세밀한 수정 요청은 다음 다섯 줄이면 충분하다.

```text
대상 상태: 메인 점수판에 플레이어가 1명 이상
대상 CTA: 점수 없이 기록하기
변경 액션: 현재 플레이어를 그대로 사용하고 인원 선택 생략
유지 영역: 게임 선택 UI, 승패/순위 UI, 기존 점수판 데이터
완료 기준: 저장·취소·새로고침 후 원래 점수판 정상 복원
```

## 11. CTA 변경 체크리스트

- [ ] 상태별 노출 CTA가 표와 일치한다.
- [ ] 문구와 접근성 이름이 실제 액션과 일치한다.
- [ ] 동일 의도 CTA가 같은 액션 함수를 호출한다.
- [ ] 숨겨진 버튼 클릭 위임이 없다.
- [ ] 중복 클릭이 차단된다.
- [ ] 취소와 뒤로 가기의 데이터 보존 범위가 명확하다.
- [ ] 새로고침 후 작성 상태가 필요한 지점에서 복원된다.
- [ ] 기존 점수판과 저장 기록이 손상되지 않는다.
- [ ] 플레이어 0명, 1명 이상, 점수 없는 결과 입력 상태를 테스트했다.
